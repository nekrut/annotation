## What I would do with it, so the decision can be judged

Checked this tick on this runner (4 cores, 15 GB RAM, no GPU, Python 3.11,
Docker client 29.3.1 present, daemon not confirmed):

- **AUGUSTUS 3.5.0** installs from Ubuntu apt in 15 s with 166 species
  parameter sets, no conda needed. I fetched the *S. pombe* panel files with
  `benchmark/fetch.py` (checksums ok) and ran
  `augustus --species=schizosaccharomyces_pombe --gff3=on --UTR=off` on the
  whole 12.57 Mb genome as one process on one core:
  **2,076 s wall clock (34.6 min), 2,073 s user, peak RSS 403 MB, 4,456
  genes, on an Intel Xeon at 2.80 GHz; that is 165 s per Mb on one core.**
  Scored with `benchmark/score.py` against the panel reference it gives
  nucleotide F1 0.95466, locus F1 0.92316 and transcript F1 0.70235, against
  0.95462 / 0.92316 / 0.70214 for T-human-007's bioconda run of the same
  tool (`benchmark/validation/augustus-Schizosaccharomyces_pombe.json`), so
  the apt build is the same predictor and the timing is comparable. One trap
  for whoever repeats it: the Debian package's species config sets
  `stopCodonExcludedFromCDS true`, so the scorer needs `--stop-outside-cds`
  (it warns loudly without it); the bioconda config did not.
  That is the first measured row of the table, and it also shows why
  T-human-007 ran chromosomes in parallel.
- **SNAP** builds from source in seconds (lenin's install table); measurable
  here the same way.
- **Helixer** has no PyPI package; the documented path is the Docker image
  above. CPU inference is possible in that image but slow; the GPU number
  should come from the same RTX 5080 the validation runs used, with the
  README's caveat that TensorFlow 2.15.1 JIT-compiles every kernel for
  sm_120 on first use, so first-run and warm-run times must be recorded
  separately.
- **Tiberius** needs Python >= 3.12 (pool finding), a 6.3 GB environment
  and an 8 GB GPU; not measurable on this runner. Same RTX 5080 plan, same
  JIT caveat, plus the 4090 figures from ANNEVO's README as a second source.
- **BRAKER3 and GeneMark-ETP**: the documented figures above, plus one
  attempted install with a stopwatch. GeneMark-ETP's unstated licence
  (lenin) is recorded, not resolved.
- **EGAPx**: documented figures only (its own README timings, the charter's
  Galaxy figures marked as charter claims since `nekrut/scalingPaper` is
  not readable by agents). If you want it measured end to end, that is a
  cluster `alert`: its README wants 32 CPUs and 256 GB; at its own AWS
  figures the smallest supported panel genome (*Ciona*, 140 Mb, no RNA-seq)
  is roughly 70 to 100 CPU-hours and 3 to 4 h wall clock per attempt.
- **Our floor**: the KA/KS run in `baselines/kaks/results/` took 365 s wall
  clock for 32 genes on four pairs, nearly all of it fetch; the test itself
  is milliseconds per window, which is the kind of number the budget section
  needs.
- **Target budget**: derive seconds per Mb on one core and on one consumer
  GPU from the rows above and from the 2M-parameter HyphAeon precedent,
  every number sourced, as the task asks.

Every measured row would carry the same declaration block as
`benchmark/validation/` (docs/benchmark.md 3.3) so cost and accuracy are
recorded on the same run.
