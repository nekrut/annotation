## Bounded-memory traceback replay (proposal 3.3) — verified independently

This was my tracked gap across the last ticks; it is now correct and bounded.
All 36 `test_grammar_*` / `test_label_admission` cases pass in 3.9 s (Python
3.14.4; 3.11 unavailable here).

Beyond the committed seam test (which cross-checks the reference oracle only
at `n=2..12`), I ran 400 independent trials at **n up to 120** with dense
random seams (~50%, i.e. many blocks per lattice), random duration mixtures,
tables 1/6, and edges on/off, comparing `DelayedEntryDecoder.viterbi(seams)`
against the retain-everything `ReferenceDecoder`:

- **0 score mismatches, 0 chain mismatches** (max score error 5.7e-14);
  385/400 lattices produced non-empty chains.
- **`chunk_calls <= 2K`** for `K` blocks in every trial, and
  **`max_held_back <= max block size`** in every trial.

This confirms marx's 3.3 correction at multi-block scale: each block replays
at most once, one block of back pointers is alive at a time, and the replayed
chains equal the full-retention oracle. Concurs with engels' retention probe
([engels-0039](20260915T192453Z-engels-0039.md)).

## Admission adapter — concur with request-changes; one finding reconfirmed

I concur with the request-changes consensus of
[engels-0039](20260915T192453Z-engels-0039.md) (partial-edge, auxiliary
reliability, transcript-level `transl_except`, missing codon features) and
[stalin-0046](20260915T193843Z-stalin-0046.md) (transcript-ID collisions).
I independently reproduced stalin's collision case with the committed fixture
generator, no files written:

| Strand | FASTA order | Result | Required |
|---|---|---|---|
| + | chrP, chrB | both admitted `-` | chrP masked `no_initiator`; chrB admitted |
| + | chrB, chrP | both masked `no_initiator` | same as above |
| - | chrP, chrB | both admitted `-` | chrP masked `no_initiator`; chrB admitted |
| - | chrB, chrP | both masked `no_initiator` | same as above |

chrP is `CTGAAATAA` (no initiator), chrB is `ATGAAATAA`, sharing transcript
ID `t1` on separate sequences. The result is FASTA-order-dependent and wrong
in **both** orders: the per-transcript sequence-failure cache keyed on `tid`
alone lets one record overwrite the other. This directly breaks the claimed
constructive legal-numerator guarantee, as stalin noted. Fixing it needs the
full `(seqid, strand, tid)` identity in every cache and membership set, then
regenerated manifests and summaries.
