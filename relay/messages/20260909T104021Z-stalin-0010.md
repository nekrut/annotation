## Structure metrics require a matching-rule qualification

The [Helixer article](https://doi.org/10.1038/s41592-025-02939-1), Methods, specifies GffCompare 0.12.8, primary transcripts selected by longest protein, and UTR removal. This resolves the draft's uncertainty about whether its structure evaluation retained UTRs. Bibliographic reconciliation: online publication was 2025-11-24; the issue citation is Nature Methods 23, 732–739 (2026). These identify one article, not separate experiments.

[Supplementary Methods S1.6.4, printed p. 11](https://media.springernature.com/original/springer-static/esm/art%3A10.1038%2Fs41592-025-02939-1/MediaObjects/41592_2025_2939_MOESM1_ESM.pdf) gives the actual preparation and scoring commands: longest-isoform filtering, removal of exon and UTR feature rows, then GffCompare with reference/output options and the query file. Neither `--strict-match` nor `-e` is supplied.

I located a [GffCompare source revision declaring version 0.12.8](https://github.com/gpertea/gffcompare/blob/30b268f6ffdf32ff54c2963ee757445d65389800/gffcompare.cpp#L6). This is version-matched source evidence, not recovery of the authors' executable. Its [option definitions and exon matcher](https://github.com/gpertea/gffcompare/blob/30b268f6ffdf32ff54c2963ee757445d65389800/gffcompare.cpp#L53) permit 100-base variation at free terminal-exon ends by default. Transcript matching applies that end-range restriction only with `--strict-match`; the [accuracy accumulation](https://github.com/gpertea/gffcompare/blob/30b268f6ffdf32ff54c2963ee757445d65389800/gffcompare.cpp#L822) promotes a returned non-strict match to a transcript true positive, including intron-chain matches with differing ends. Single-exon matching also has overlap-based semantics in the usage description.

**Inference:** removing UTRs does not by itself make these reported exon/transcript metrics require exact coding starts and stops. Retain the original scores with the evaluator and options attached; do not relabel them exact-CDS recovery. A new benchmark should score explicit coding coordinates and phases, and separately preserve the native comparator endpoint. This audit does not quantify how many published matches would fail a stricter test; no GffCompare binary was run.

## Pinning source alone does not pin automatic checkpoint selection

[helixer/core/data.py](https://github.com/usadellab/Helixer/blob/d17bb496b8842542590644b2437798711c0125d5/helixer/core/data.py#L10) obtains the model catalog from a moving `main` URL, falling back to a locally saved catalog on a request exception. It recognizes installed files by name and selects the lowest numerical catalog priority among those present. A newer unavailable model triggers a notice rather than an inference-time weight download.

An isolated check executed only the inspected `identify_current` function, with directory listing replaced by two synthetic filenames. Swapping their catalog priorities while holding that listing fixed changed the selected filename as expected. No weight or filesystem contents were accessed by that function.

**Inference:** reproducible comparisons need the chosen weight file and checksum, not just a code commit and `--lineage`. The [explicit-file argument branch](https://github.com/usadellab/Helixer/blob/d17bb496b8842542590644b2437798711c0125d5/Helixer.py#L123) bypasses automatic selection and requires a subsequence length. Effective lineage defaults are fungi 21,384; plants 64,152; vertebrates and invertebrates 213,840 bases. Overlap defaults derive from that length. Record these input-context choices with the checkpoint; a context length alone is not evidence of a hard maximum gene length.

## Runtime boundary and hardware

The [main article's Benchmarking section](https://doi.org/10.1038/s41592-025-02939-1) reports 27 minutes for the 263-Mbp Oryza brachyantha genome and just under 8.5 hours for the 3.3-Gbp human genome. These are author measurements.

[Supplement S1.7, printed p. 12](https://media.springernature.com/original/springer-static/esm/art%3A10.1038%2Fs41592-025-02939-1/MediaObjects/41592_2025_2939_MOESM1_ESM.pdf) defines the workload as sequence conversion, neural prediction and HMM postprocessing. Workstation A uses Ryzen 9 5950X, GTX 1080 Ti with 11 GB, 32 GiB RAM and NVMe storage; inter-tool workstation C uses Xeon W-2125, GTX 1080 with 8 GB and 32 GB RAM. All benchmarks disable multiprocessing and use lzf compression and SSD temporary storage; batch sizes are 64 for A/B and 58 for C. **Inference:** the paper's single-threaded description must retain its GPU context; it is not a CPU-only cost claim. Installed RAM is not measured peak memory.
