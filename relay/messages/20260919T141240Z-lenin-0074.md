Landed the section 3.6 structured **training-window loader** for candidate A on
`work/T-human-014-lenin` (commit 267b34d, [PR #38](https://github.com/nekrut/annotation/pull/38)),
the piece that connects the encoder emissions and the chain-loss oracle to real
admitted labels.

- `model/a/dataset.py` `verify_source` — hard checksum gate: recomputes the GFF3
  and FASTA MD5s and refuses any file not matching the species' `*.summary.json`
  digests (FASTA presence must match too). A window from an unpinned file is not
  the audited label.
- `iter_windows` — delegates admission to `model.labels.admission.audit_species`
  (same `m`/`table` as the committed manifests), so the yielded set is exactly
  the admitted representatives; it never re-derives the metadata/sequence audit.
  Each admitted chain is rejoined to the checksummed FASTA via
  `numerator_check.oriented_chain` and returned as a `WindowExample` (oriented
  window, merged half-open CDS/intron ranges, table id, source identity) whose
  `.support()` delegates to `numerator_scores`.
- Scoped to the complete-target oracle: edge-partial admitted chains and
  windows over a caller's `max_window` are skipped and counted in `LoaderStats`,
  never capping gene length by the encoder core.

`tests/test_a_dataset.py` (6 stdlib cases) builds a synthetic admitted two-exon
gene on a 10 kb contig: checksum gate (match / tampered FASTA / FASTA-presence
mismatch), window coordinates and identity, the `max_window` skip counter, and
the numerator→gold Viterbi round trip through `chain_nll`. Full candidate-A
suite: 29 run, 10 torch-gated skipped, all pass (no torch, Python 3.14.4).

Still open before measurement (unchanged asks): the boundary-support path for
edge-partial numerators (edge-enabled decoder), whole-gene cropping into the
encoder core with retained state, the batched torch chain loss matching this
oracle, PyTorch forward/backward + instantiated param-count + Python 3.11, then
a gagarin compute-request. Training/cluster CPU-hours 0, GPU-hours 0 this tick.
