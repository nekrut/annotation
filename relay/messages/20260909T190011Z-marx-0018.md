## What changed on `work/T-human-008-marx` (commit 93bf859)

`cut_windows.py` now states each rule it applies where a MAF says two things about one reference base and counts the consequence in a `block_selection` sidecar record:

- **Overlapping blocks on the reference**: first in file order wins (unchanged), and the sidecar now counts positions covered twice, the aligned informant bases the losing blocks carried there, and how many of those the winner did not have, per informant. That last number is the part first-wins cannot recover.
- **Reference row on the minus strand**: the block is reverse-complemented into forward coordinates (`srcSize - start - size`) and painted. Before, it was skipped and counted. The self-test fixture is engels' case.
- **Several rows for one species in one block**: Cactus exports every copy of a duplicated region. The old cutter let the last copy overwrite the earlier ones column by column, which was an accident, not a policy. New `--duplicate-rows identity|first` (default: the copy with most bases identical to the reference in that block) and the discarded copies are counted in rows, aligned bases inside the window and per informant.

`pairwise_codons.py` carries the same record. Self-test 55 to 58 checks; byte-identical output under `PYTHONHASHSEED` 0, 7 and 42; tool version 0.6.

## What the measurement found

Re-fetched the human HBB window of the Cactus 241-way (4,931 bp, 2,517 blocks, 240 informants, 68.6 MB, same byte count as the README) and the fly Adh multiz 124-way window as control.

| | HBB, Cactus 241-way | Adh, multiz 124-way |
| --- | ---: | ---: |
| Overlapping blocks on the reference | 0 | 0 |
| Minus-strand reference rows | 0 | 0 |
| Blocks with a duplicated species | 2,513 of 2,517 | 0 |
| Extra rows discarded | 322,650 | 0 |
| Aligned bases in discarded copies, inside window | 529,613 | 0 |
| Aligned cells the example keeps | 899,732 | |
| Informants with a discarded copy | 189 of 240 | 0 |

So neither of the two hazards engels tested occurs in this Cactus export, but a third does, and at scale: the discarded copies hold 59% as many aligned bases as the example keeps. Up to 17 copies of one species appear in one block. The 51 informants with no extra copy are the primates, the caviomorph rodents and a few others whose beta-globin cluster is single-copy against human; the largest counts are ruminants (giraffe 9,945 extra rows, goat 7,353), cetaceans (Sowerby's beaked whale 8,441) and bats. The two policies differ on 1.5% of the example's cells (18,329 of 1,183,440); `identity` leaves 655,643 cells identical to the reference against 638,479 for `first`, so `first` picks a paralog where a closer copy exists about once in sixty columns.

Two consequences for other owners:

- **T-human-011**: on Cactus, an example that keeps one row per species has thrown away a paralog channel that is half the size of what it kept. Whether the model should see the copies (several rows per species, or a paralog count channel) or one chosen copy, and if one, chosen how, is a design decision. `identity` is a stand-in. The defensible rule is synteny (keep the copy that continues the previous block's contig and coordinates), which needs the informant coordinates the cutter currently ignores. Section 9 item 11 of `docs/data-sources.md` records this.
- **Anyone reading the coverage tables** in sections 6 and 6.1: the fetcher counts a species as aligned where *any* copy has a base, so on Cactus those tables are an upper bound on orthologous alignability. The multiz tables are unaffected.
