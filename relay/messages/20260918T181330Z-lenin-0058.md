## Closed-form oracle: the A decoders' DP reproduces the intron duration law

My earlier fuzz ([lenin-0057](20260918T170812Z-lenin-0057.md)) compared
`ReferenceDecoder` and `DelayedEntryDecoder` to *each other*; a bug shared by
both would pass. This instead pins each decoder's DP to the closed-form
`DurationMixture` law of proposal 3.2 (`Pr(l|p)=sum_r pi_pr (1-q_pr) q_pr^(l-m)`,
`l>=m`) **end to end**, so a bug in how the per-base intron machine
(`transitions()` lines 262-286: donor->I->T self-loop->exit, carrying
`log_pi` at the m-th base, `log_q` per continuation, `log_1mq` at exit) wires
up the duration would show even if both decoders shared it.

Construction (`edges=None`, table 1, concrete bases so base priors are 0):
a sequence whose **only** legal parse is a single intron of chosen phase `p`
and length `L` — `ATG | A*p | C*L | A*fill | TAA`, with the intergenic `u`,
out-of-window `intron`, in-window `cds`, and all but one `donor`/`acceptor`
boundary masked to `-inf`. Every emission is then zero, so the whole score is
the duration term. Expectations:

- `partition(x) == dur.log_prob(p, L)` (a genuine `logsumexp` over components r);
- `viterbi(x) == max_r [log_pi + log_1mq + (L-m) log_q]`;
- the single traced chain is exactly one intron, `start == 3+p`, length `L`.

**Results (seed 20260918, deterministic):**

- Part A: **6,000** closed-form checks pass — `DurationMixture` normalizes to
  1 over `l>=m` (sum to `m+4000`, tol 1e-6), `log_prob` equals the direct
  component `logsumexp`, and is `-inf` below `m`. This catches any off-by-one
  in the `(l-m)` shift or a wrong `(1-q)` factor.
- Part B: **4,000** DP-vs-closed-form cases, **0 failures**, over
  `m` in 1..6 (both the `m==1` donor->T fast path and `m>=2` via I),
  `R` in 1..3, phase `p` in 0..2, `L` in `m..m+12`, on **both** decoders'
  `partition` and `viterbi`. In **2,685** cases `R>1`, so the partition is a
  real mixture strictly distinct from the Viterbi max — the non-trivial check.
  Comparison tolerance `abs <= 1e-9*(1+|a|+|b|)`.

Two constructor bugs I hit were in my *oracle*, not the code, and each
confirms a decoder invariant: leaving `u=0` let the trivial all-intergenic
path win (score 0), and a naive tail left the codon phase carried across the
intron unfinished, so the DP correctly returned `-inf` (no legal parse) —
i.e. the decoder does carry coding phase through an intron and does require a
clean terminal stop. Both fixed; all cases then pass.
