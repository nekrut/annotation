## EGAPx can adapt its HMM to the target genome

All code observations below use EGAPx commit [`f9a7392b6f60d0d24f28db5c4eb69b0e1984616b`](https://github.com/ncbi/egapx/tree/f9a7392b6f60d0d24f28db5c4eb69b0e1984616b), committed 2026-09-04. The current [README](https://github.com/ncbi/egapx/blob/f9a7392b6f60d0d24f28db5c4eb69b0e1984616b/README.md#input-data-format) requires genome and taxid; RNA-seq is recommended. An omitted protein set can be selected automatically, so a minimal input YAML does not mean DNA-only prediction. The documented exclusions for fungi, protists and nematodes remain.

In [egapx.py](https://github.com/ncbi/egapx/blob/f9a7392b6f60d0d24f28db5c4eb69b0e1984616b/ui/egapx.py#L1328), `train_hmm` defaults to the inverse of `get_closest_hmm`'s good-match flag. A supplied HMM defaults to no training; an explicit `train_hmm` setting takes precedence. The selector accepts a shared genus, a shared family for mammals, or a fully matched candidate lineage as a good match. This is taxonomic selection, not an empirical accuracy test.

The [Gnomon workflow](https://github.com/ncbi/egapx/blob/f9a7392b6f60d0d24f28db5c4eb69b0e1984616b/nf/subworkflows/ncbi/gnomon/main.nf#L104) either reuses the supplied parameters or calls a [training workflow with four sequential iterations](https://github.com/ncbi/egapx/blob/f9a7392b6f60d0d24f28db5c4eb69b0e1984616b/nf/subworkflows/ncbi/gnomon-training-iteration/gnomon_training_iterations/main.nf#L24). Each [iteration](https://github.com/ncbi/egapx/blob/f9a7392b6f60d0d24f28db5c4eb69b0e1984616b/nf/subworkflows/ncbi/gnomon-training-iteration/utilities.nf#L24) chains evidence, predicts models, then trains parameters from those models on the target genome.

**Review implication:** describe EGAPx as evidence-based prediction with taxonomic parameter selection and conditional target adaptation. Its defaults do not establish a single fixed model transferring across clades. Benchmark manifests should retain the selected HMM and its hash, training flag, effective parameters, protein membership and evidence versions. Runtime comparisons should state whether this training branch ran.

## The default intron limit also depends on genome size

The [selector](https://github.com/ncbi/egapx/blob/f9a7392b6f60d0d24f28db5c4eb69b0e1984616b/ui/egapx.py#L2194) returns these base limits and scaling thresholds:

| Taxonomic branch | Base maximum intron (bp) | Genome-size threshold (bp) |
| --- | ---: | ---: |
| Viridiplantae | 300,000 | 3,000,000,000 |
| Vertebrata | 1,200,000 | 2,000,000,000 |
| Other | 600,000 | 500,000,000 |

For genomes below the threshold, [setup/main.nf](https://github.com/ncbi/egapx/blob/f9a7392b6f60d0d24f28db5c4eb69b0e1984616b/nf/subworkflows/ncbi/setup/main.nf#L129) uses integer arithmetic to scale the base limit by genome size and round the resulting integer up to a 100,000-bp increment. At or above the threshold it retains the base limit. Supplying `max_intron` explicitly sets the threshold to zero and bypasses scaling.

The [main workflow](https://github.com/ncbi/egapx/blob/f9a7392b6f60d0d24f28db5c4eb69b0e1984616b/nf/subworkflows/ncbi/main.nf#L110) passes the effective value to protein alignment, short-read and long-read alignment, and Gnomon workflows. The [training wrapper](https://github.com/ncbi/egapx/blob/f9a7392b6f60d0d24f28db5c4eb69b0e1984616b/nf/subworkflows/ncbi/gnomon/gnomon_training/main.nf#L30) replaces its default `-maxintron` with this value. This is verified parameter flow, not a demonstration that every downstream component enforces an identical strict cutoff.

**Inference:** stratifying an EGAPx benchmark by intron length should retain this effective limit. A default changing with genome size can affect evidence generation before final gene decoding. Its accuracy impact remains unmeasured here.

## RefSeq is a distinct reference endpoint

NCBI's [annotation-process documentation](https://www.ncbi.nlm.nih.gov/refseq/annotation_euk/process/#choosing-the-best-models-for-a-gene) gives precedence to known RefSeq transcript alignments and selects a supported subset of Gnomon models. It also describes models compensating for assembly frameshifts or stop codons, and products that can differ from literal genomic translation. Consequently, a RefSeq annotation should not be described simply as raw EGAPx output. **Inference:** benchmark reference parsing needs explicit treatment of partial models and translation exceptions, alongside independent evidence provenance. This concerns evaluation of protein-coding structures; no additional annotation work was undertaken.
