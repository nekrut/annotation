## Finetuning epochs are a sampling budget

The pinned CLI sets gradient accumulation to `64 / finetune_B` and training steps per epoch to `100 * gradient_accumulation_steps`. Therefore each completed epoch consumes 6,400 windows, independent of the supported physical batch size. The default ten epochs consume 64,000 windows. The loader samples genomic windows repeatedly; an epoch is not a traversal of every genome base. These are source-derived budgets, not measured training throughput. [CLI overrides](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/vipsania/cli/annotate.py#L161), [fit call](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/vipsania/train/trainer.py#L318), [sampler](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/vipsania/data/dataset.py#L195).

Training context length remains the loaded model's `dataset.T`; the annotation CLI's `--context` is not copied into that dataset override. For the repository's base-25M configuration, `dataset.T=20,000`, so the default ten epochs present 1.28 billion nucleotide positions, counting repeated sampling. This does not mean 1.28 billion distinct bases, a fixed fraction of a genome, or that every released checkpoint uses this configuration. The annotation context default is 200,000. [Base configuration](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/configs/base_25M.json#L60), [CLI defaults and overrides](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/vipsania/cli/annotate.py#L80).

Consequently, an adaptation cost comparison should record loaded training context, sampled windows, repeat rejection, elapsed time, and annotation time. Genome size alone does not specify how much sequence the optimizer sees.

## Output sequence filters do not define the adaptation split

`--include` and `--exclude` reach `annotate_genome`, but the finetuning override supplies the entire FASTA through `train_paths=[fasta]`. The indexed loader enumerates its sequence names independently. To exclude a chromosome from adaptation, prepare a separate training input; restricting annotation output does not achieve that split. This is target-sequence exposure, not evidence of annotation-label leakage. [CLI data path and output caller](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/vipsania/cli/annotate.py#L183), [loader enumeration](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/vipsania/data/dataset.py#L173).

The default repeat threshold also depends on the entire input FASTA: below one billion bases, the repeat filter is disabled; at or above that boundary, training chunks with more than 25% lowercase repeat positions are rejected. `--drop_repeats` overrides the choice. `--relax_repeats` enables an adaptive threshold, so it changes the sampled training distribution as well as sampling speed. Sequence weights are proportional to `max(0, sequence_length - dataset.T + 1)`, giving contigs shorter than the training context no sampling weight. These restrictions apply to adaptation; they do not establish an annotation recall ceiling. [Threshold selection](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/vipsania/cli/annotate.py#L166), [repeat filter](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/vipsania/data/util.py#L83), [relaxation](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/vipsania/data/watch.py#L89), [sequence weights](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/vipsania/data/dataset.py#L176).

My benchmark recommendation: distinguish frozen inference from target adaptation, and record both the adapted sequence set and the output sequence set. Preserve repeat-mask provenance and the resolved sampling threshold, including relaxation history.

## Trace active checkpoint selection before inferring supervision

The repository includes an optional callback that compares annotations with a reference. Its existence does not demonstrate its use in CLI finetuning. The inspected CLI uses `finetune=True`, `resume=False`, and no validation paths. These settings yield `load=True`, so `Trainer.train` adds essential callbacks only; the optional annotation/validation callbacks are omitted. The essential checkpoint callback saves the latest weights without a best-score criterion. The CLI then annotates with `trainer.model`; this inspected path does not choose between pretrained and adapted weights using reference accuracy or held-out loss. Paper-level model-selection provenance remains unresolved. [Trainer flags](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/vipsania/train/trainer.py#L78), [callback gate and latest checkpoint](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/vipsania/train/trainer.py#L304), [CLI model handoff](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/vipsania/cli/annotate.py#L204), [optional annotation callback](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/vipsania/train/callback.py#L284).
