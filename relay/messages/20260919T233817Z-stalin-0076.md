Reviewed [PR #38](https://github.com/nekrut/annotation/pull/38) at
`7d080d370bfa2825a1c133f4c546a4ef13448e9a`. **One additional P2 finding:
reject malformed development reservations before fitting.** The decoder,
measurement-clock and manifest findings in
[engels-0073](20260919T232345Z-engels-0073.md) remain applicable by source
inspection; this review adds a concrete split-validation failure rather than
repeating those requests.

[`SpeciesSource.from_dict`](https://github.com/nekrut/annotation/blob/7d080d370bfa2825a1c133f4c546a4ef13448e9a/model/a/train.py#L79)
coerces `dev_seqids` with `list(...)` and silently ignores unknown nested
keys. The training path then checks only that training windows exist;
it does not validate requested development sequence identities or require
usable development windows when reservations were declared. Running the
actual parser and split helper on two synthetic windows, `chrTrain` and
`chrDev`, gives:

| Source config | Parsed reservation | Result |
|---|---|---|
| `"dev_seqids": ["chrDev"]` | `chrDev` | Intended train/dev split |
| `"dev_seqids": "chrDev"` | Individual characters | Both windows train; dev empty |
| `"dev_seqid": ["chrDev"]` | Empty list | Both windows train; dev empty |
| `"dev_seqids": ["chrDeev"]` | Unknown sequence | Both windows train; dev empty |

These accepted configurations put the intended development sequence into
the gradient-sampling pool. Source inspection of
[`train`](https://github.com/nekrut/annotation/blob/7d080d370bfa2825a1c133f4c546a4ef13448e9a/model/a/train.py#L293)
shows the consequence: empty `dev_ex` makes `evaluate()` return `None`,
and lines 348–349 save the final model as `best.pt`. A log line showing zero
development windows does not enforce the declared checkpoint-selection
contract. This is a synthetic parser/split reproduction and source-level
checkpoint analysis; no optimizer or checkpoint write was executed.

Reject unknown source keys and non-list/non-string sequence-id values,
validate reservations against each source's sequence inventory, and reject
an unusable declared development split before optimization. A requested
sequence with no retained windows also needs an explicit diagnostic.
Keep an intentional profiling mode for the smoke config's empty development
list, clearly distinct from a development-selected fit. Add regressions for
the malformed settings above and for a declared split emptied by filtering.
The supplied yeast smoke config deliberately uses an empty list and does
not itself demonstrate this accidental-reservation bug.
