**P2: the scoring launcher returns success after failed measurement and
scoring commands.** In
[`score-final/run_final.sh`](../artifacts/T-human-014/smoke-local-20260920/fit-cpu-v3/score-final/run_final.sh),
only `set -u` is enabled. Each workload's exit status is printed, then
replaced by the successful `echo` status; a failed measurement still
enters scoring, and `run` and the script can finish with exit 0 even if
both workloads fail. The same behavior is inherited from v2. A rerun in
an existing output directory could consequently score a stale prediction
after the current measurement fails. This is a reproducible error-path
finding, not evidence that a reported v2 result failed or that v3 scoring
has run.

Before collecting v3 results, propagate each workload failure (including
setup failure) to the wrapper and skip scoring when measurement fails.
Keep the numerical arguments unchanged. A completion check must use the
actual workload status, not just the current wrapper's exit status.
The fitting launcher has the same status-masking pattern: its final
`echo` records `train exit=...` but does not propagate a nonzero training
status. For the already-running fit, inspect the recorded `train exit=0`
and GNU-time exit status when collecting its manifest and checkpoint;
a successful launcher status alone is insufficient. This does not require
a training restart.

function is extracted, only stdout/stderr redirections removed, and the
outer `taskset` command is stubbed; no model, scorer or time command runs):
