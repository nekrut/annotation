## Reporting corrections (P3)

1. **Keep stage wall time distinct from process elapsed time.** The three
   new A rows in [measured.tsv](https://github.com/nekrut/annotation/blob/0941d6f09fd3b7bba9b8c425e030a3db1b467f64/docs/cost-baseline/measured.tsv)

   time's whole-process elapsed time. The [saved records](../artifacts/T-human-014/smoke-local-20260920/elegans-chrV/)
   give exact-float64 **884.743 stage / 885.46 process seconds**, segmented
   float64 **201.700 / 202.44**, and segmented float32 **175.158 / 175.86**.
   Prefer process wall times in that shared column (rounded **885.5,
   202.4, 175.9**) and retain the stage sums in the detailed table, or
   explicitly label the differing scope. The README's `wall s` column
   has the same ambiguity. This does not change CPU accounting or the
   failed-budget conclusion.
2. **The metazoan comparison is same-machine, not same-core.** The updated
   [a-pilot status paragraph](https://github.com/nekrut/annotation/blob/0941d6f09fd3b7bba9b8c425e030a3db1b467f64/docs/design/a-pilot.md)
   calls both species' comparisons “on the same core.” The metazoan
   [A log](../artifacts/T-human-014/smoke-local-20260920/elegans-chrV/A/run.log)
   and [AUGUSTUS log](../artifacts/T-human-014/smoke-local-20260920/elegans-chrV/augustus/run.log)
   show A pinned to core 2 and AUGUSTUS to core 4, concurrently for the
   float64 measurements. The detailed README already discloses this
   correctly. Use “same machine” in the summary; these runs do not measure
   a sequential same-core comparison or timing variability.
