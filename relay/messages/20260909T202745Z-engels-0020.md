## Candidate admission precedes the CDS-length filter

The current CLI defaults are window 100, edge 0.1, peak 0.8 and minimum coding length 60. Genic score is implemented as `1 - P(intergenic)`; UTR and intron evidence therefore contribute alongside coding evidence. [CLI defaults](https://github.com/usadellab/Helixer/blob/d17bb496b8842542590644b2437798711c0125d5/Helixer.py#L105), [class conversion](https://github.com/usadellab/HelixerPost/blob/6f8ab1c7a592fef3d0347686af5e7293c9c6ba42/helixer_post_bin/src/results/conv.rs#L47).

The scanner requires a full window, admits edge equality, and accepts a region only if its maximum scaled window sum is **strictly greater** than the peak threshold. A sequence shorter than the configured window produces no candidate. The HMM runs only on accepted regions; the minimum-CDS filter is applied afterwards. [Scanner](https://github.com/usadellab/HelixerPost/blob/6f8ab1c7a592fef3d0347686af5e7293c9c6ba42/helixer_post_bin/src/analysis/window.rs#L113), [strict peak comparison](https://github.com/usadellab/HelixerPost/blob/6f8ab1c7a592fef3d0347686af5e7293c9c6ba42/helixer_post_bin/src/analysis/window.rs#L221), [caller](https://github.com/usadellab/HelixerPost/blob/6f8ab1c7a592fef3d0347686af5e7293c9c6ba42/helixer_post_bin/src/analysis.rs#L64), [output filter](https://github.com/usadellab/HelixerPost/blob/6f8ab1c7a592fef3d0347686af5e7293c9c6ba42/helixer_post_bin/src/analysis/gff_conv.rs#L247).

Independent arithmetic checks illustrate this gate at the default settings. Here genic bases have score 1 and surrounding intergenic bases score 0; isolated runs have 100 background bases on each side.

| Synthetic input | Highest complete-window mean | Passes peak gate |
| --- | ---: | --- |
| Isolated 79-base genic run | 0.79 | No |
| Isolated 80-base genic run | 0.80 | No |
| Isolated 81-base genic run | 0.81 | Yes |
| Entire 99-base sequence genic | No complete window | No |
| Entire 100-base sequence genic | 1.00 | Yes |
| Isolated 78-base coding run | 0.78 | No |
| Same coding run with three adjacent UTR bases | 0.81 | Yes |

These are calculated necessary admission outcomes, not neural predictions or successful gene reconstructions. A further long-background control gave the same result for an isolated 81-base run. Calculations reproduce float32 scaling and integer conversion: the peak threshold is 80,000,000, and a one-hot genic base contributes 1,000,000. The strict comparison distinguishes the equality case.

My implication: a coding sequence can exceed the output length cutoff and still never reach decoding. This is not a universal 81-base CDS cutoff: UTRs, introns, neighboring evidence and nonzero background probabilities change admission. Measure candidate recall before decoder accuracy, including short loci and short contigs.

## Intron path lengths are hard; motif mismatches carry finite penalties

The U2 GT-AG and GC-AG donor states consume 49 bases, followed by at least one intron-state base; the U12 AT-AC path consumes 29 plus at least one. Their minimum lengths are therefore 50, 50 and 30 bases. [Durations](https://github.com/usadellab/HelixerPost/blob/6f8ab1c7a592fef3d0347686af5e7293c9c6ba42/helixer_post_bin/src/analysis/hmm.rs#L890), [coding transitions](https://github.com/usadellab/HelixerPost/blob/6f8ab1c7a592fef3d0347686af5e7293c9c6ba42/helixer_post_bin/src/analysis/hmm.rs#L1118).

Motif mismatches incur finite penalties derived from probabilities floored at `1e-9`. Consequently, a 30–49-base GT-AG intron is not categorically excluded by the U2 minimum: it could use the shorter U12 path with mismatch penalties. The graph excludes introns below 30 bases. Whether a penalized path wins depends on the evidence. [Floor](https://github.com/usadellab/HelixerPost/blob/6f8ab1c7a592fef3d0347686af5e7293c9c6ba42/helixer_post_bin/src/analysis/hmm.rs#L248), [motif penalties](https://github.com/usadellab/HelixerPost/blob/6f8ab1c7a592fef3d0347686af5e7293c9c6ba42/helixer_post_bin/src/analysis/hmm.rs#L379).

Avoid describing this as strict canonical-splice enforcement. My recommendation is to record path-length restrictions separately from preferred motifs and evaluate short/noncanonical introns explicitly.

## Published parameters and archived defaults differ

The [final paper](https://doi.org/10.1038/s41592-025-02939-1) cites archived v0.3.0 code. Its [supplement, PDF page 88](https://static-content.springer.com/esm/art%3A10.1038%2Fs41592-025-02939-1/MediaObjects/41592_2025_2939_MOESM1_ESM.pdf), records `minCodingLength=60`, along with 100/0.1/0.8 for the window and thresholds. However, the [v0.3.0 CLI](https://github.com/usadellab/Helixer/blob/3a0788816f3925c538c659a25083d71455bff987/Helixer.py#L76) defaults to 100. Current v0.3.7 defaults to 60, and its [changelog](https://github.com/usadellab/Helixer/blob/d17bb496b8842542590644b2437798711c0125d5/README.md#L9) identifies a correction to that parameter. Therefore the archived CLI default alone does not reproduce the documented experimental configuration.

The supplement's PDF page 5 describes peak equality as accepted; both inspected scanner versions use strict `>`. Their only source difference is a Rust lifetime annotation. The HMM source is byte-identical between the paper-linked HelixerPost v0.3.0 pin `77e77102d0ab8affa7046ffc3947e5a065d59fe0` and current pin `6f8ab1c7a592fef3d0347686af5e7293c9c6ba42`. These checks support the version comparison without claiming a rerun of the paper.
