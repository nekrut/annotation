## An identity run pins only the fixed points

Nine submissions have now been scored, and every one of them was checked
against an identity run first: the reference scored against itself, every
metric 1.0, 0 fusions, 0 splits. That control cannot fail for the wrong
reason -- a scorer that silently dropped the same annotation from both sides
would pass it. So `benchmark/degrade.py` now makes a *known* perturbation
instead: delete 10% of transcripts, move the downstream boundary in
transcription order of 10% of CDS segments 3 bp further downstream, seeded and
reproducible. Degraded-copy coverage went from 2 of 20 panel species to 20 of
20; the scored results are in `benchmark/validation/degraded/`.

## The perturbation is asymmetric on purpose

Which coordinate a "downstream" shift moves depends on the strand: `end` on
`+`, `start` on `-`. So it lands on stop codons and **donor** sites and never
touches start codons or **acceptor** sites. A scorer whose splice-site or
codon assignment is not strand-aware cannot reproduce that. All 20 species do:
donor F1 0.811-0.870 against acceptor F1 0.934-0.989, and **locus precision
and start-codon precision are exactly 1.0 on every species**, over 775,253
scored reference transcripts -- zero invented loci, zero invented start
codons. The earlier two-species version of this control reported human start
F1 0.912 *with* false positives, which was correct for the ad-hoc script that
produced it: it moved the `end` field regardless of strand, so on roughly half
the annotation it was perturbing start codons while the write-up said stop
codons. That is the argument for the perturbation being a reviewable file
rather than a shell one-liner.

## Two findings other agents' tasks may care about

**Fusion and split counts are not invariant under a perturbation that is
neither a fusion nor a split.** Six species report 1 or 2 fusions and six
report 1 to 8 splits on input that only deletes transcripts and moves
boundaries 3 bp. Running each perturbation alone at the same seed separates
them exactly: every split comes from the deletions (human 8, *A. mellifera* 2,
*X. tropicalis* 1), every fusion from the 3 bp shifts (human 1,
*A. mellifera* 1). Both are the specified behaviour -- deleting an isoform can
pull a gene out of the prediction's own CDS-overlap graph, and a 3 bp
extension can bridge a same-strand gene pair the reference kept 1 to 3 bp
apart -- but the practical consequence is that a fusion or split count in the
low single digits is inside the noise a structurally *correct* submission can
produce on a 20,000-gene annotation. Report it; do not rank on it. This is
relevant to anyone reading a §4.4 number off a future run.

**The transcript level is the metric that responds to per-segment error.**
Transcript F1 runs from 0.841 on *S. cerevisiae* (1.05 exons per transcript)
to 0.365 on *T. rubripes* (14.4), while nucleotide F1 over the same species
moves only from 0.943 to 0.972 -- and upwards, because an intron-rich genome
has more CDS bases to absorb the same 3 bp. A per-base score and a per-chain
score are not two views of one quantity.

## A defect the control found in the control

The ablation above is what caught it, and the combined run could not have.
The first `degrade.py` drew the per-segment shift only for CDS lines that
survived the deletion pass, which makes the shift stream a function of the
drop rate: a drop-only run and a combined run at the same seed then shift
different segments, and the ablation is not a decomposition of the combined
run at all. *T. rubripes* is where it surfaced -- the combined run reported one
fusion that neither single perturbation could produce, which is impossible,
since a combined prediction's CDS blocks are a subset of the shift-only one's.
The shift is now drawn for every CDS line and applied only to the survivors,
and the self-test asserts over four seeds that a combined run's surviving CDS
coordinates equal the shift-only run's. That check fails on the pre-fix code.
