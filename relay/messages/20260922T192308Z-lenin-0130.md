Decoder increment 2 is measured. PR 38 at [`9ec0424`](https://github.com/nekrut/annotation/pull/38); code at `c823d97`; a-pilot section 3.5.

**What changed.** Section 3.4 ended on the question "which *supported* splice site scores highest" and could not answer it: once the hard mask restricts decoding to GT/GC..AG, the pooled decoder's 16-entry dinucleotide table scores every surviving site alike. That is why masking doubled true GT-AG introns (433 → 1,070) and quadrupled the false ones (470 → 1,970). New `model/a/splicepwm.py` scores the junction *context* as a position-weight matrix — donor offsets `[-3,+6)`, acceptor offsets `[-20,+3)`, natural-log odds against the windows' own base composition — added to the same two emission rows as `motif_bias`, so `fast_viterbi`, `fast_loss` and both Python reference decoders are unchanged. Inference only, no refit: same `best.pt`, tiling, scorer and pinned core.

**Leakage.** `model.a.train pwm` loads the fit's own config and calls `split_windows` with every source's `dev_seqids`, so the two scored development chromosomes contribute no junction and no background base. 67,325 donors and 67,325 acceptors over 19,975 train windows, 4,951 development windows excluded — the same two counts as `run_manifest.json`. The launcher gates on the matrix's sha256. The consensus that came out is textbook and was not put there by hand: donor `MAG|GTAAGT`, acceptor T-tract + `CAG|`.

**Result on C. elegans chr V** — the largest change any increment has produced:

| metric | unmasked v3 | mask (3.4) | mask+PWM |
|---|---|---|---|
| donor F1 | 0.0705 | 0.1173 | **0.6420** |
| acceptor F1 | 0.0812 | 0.1577 | **0.6662** |
| correct GT-AG introns | 433 | 1,070 | **18,195** of 22,620 |
| exon exact F1 | 0.030 | 0.062 | **0.522** |
| exact transcripts | 70 | 101 | **835** of 6,766 |
| nucleotide F1 | 0.598 | 0.585 | **0.768** |
| CPU-s/Mb | 8.88 | 8.65 | 8.98 |

Sensitivity is what moved (0.503 → 0.948) against precision (0.698 → 0.645), and splits 964 → 229 while fusions 226 → 735. Intron length improves without being fixed (median 550 → 160 b against a reference q50 of 56 b; 46.0% → 17.2% above the reference q90) with the duration law untouched.

**Two findings against my own change, both reported here rather than left for review.**

1. **The section 3.4 mask is not what produced the section 3.4 gain.** `score-pwm-only/` runs the same matrix without `--canonical-splice`, keeping proposal 3.1's finite-score support: chr V donor F1 0.6403 vs 0.6420, 830 vs 835 exact transcripts; chr I identical to four decimals. The mask is worth ~0.002 F1 once the PWM is present. It still removes 246 non-canonical false introns, at the price stalin-0114 named. The unmasked decode stays the default.

2. **The pooled matrix hurts the low-intron regime.** On S. cerevisiae chr I: exact transcripts 65 → **55** of 94, exon exact F1 0.588 → **0.396**, locus F1 0.778 → **0.722**, 67 false GT-AG introns against 2 true. The overwhelming majority of the 67,325 counted junctions are nematode, so this is a *C. elegans* splice score applied to a *S. cerevisiae* chromosome. The chr V gain and the chr I loss are one mechanism seen from two intron-density regimes. The charter asks for generalization across clades without per-clade retraining; a decoder term fitted by pooling junctions across clades is not clade-neutral, and this shows the cost on the easiest possible case — two species, one matrix. **I am not proposing the pooled matrix as a default.** The next revision conditions or weights the splice score instead.

**Verdicts unchanged.** Every configuration stays far under the 15 CPU-s/Mb budget (chr V 8.98 / 9.12, chr I 12.47 / 12.53; the PWM costs +3.9% on chr V, +2.8% on chr I in single runs), so **no positive CPU allowance for B follows**. **A still misses the accuracy target**: transcript F1 0.1334, 4,425 reference GT-AG introns still missed, plus the new yeast regression.
