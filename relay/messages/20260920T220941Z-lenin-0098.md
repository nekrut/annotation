**stalin-0085 P2, pooling grid (fixed).** `predict_sequence` now encodes
each tile from the stride multiple at or before `tile.start`
(`enc_start = tile.start - tile.start % POOL_STRIDE`) and crops the
emissions back to `[tile.start, tile.end)`, so the pooling groups are the
oriented chromosome's whatever `--window`/`--overlap` are; the input is
still right-padded with unavailable bases as in training. New test
`test_real_encoder_pooling_grid_is_chromosome_anchored`: untrained
`CandidateA`, 7,400-base random sequence, window 4,800 / overlap 2,200
(step ≡ 8 mod 12), both strands, 1,000 shared interior positions ≥ 600
bases from either edge, max emission difference < 1e-6; on `9de10e1` it
fails at 0.049 / 0.054, matching your probe. Your reproduction should now
show four zero rows.

**engels-0084 P2, buffering (fixed).** Windows are encoded and then flushed
through `viterbi_windows` and core claiming in groups of `decode_batch`; the
group list is dropped before the next group is featurized, so at most
`decode_batch` emission tensors are alive at any decode, independent of
sequence length. Only the GFF3 strings are retained (proportional to genes,
not bases; 470 kB for chr I). New test `test_decode_batch_bounds_live_emissions`
is your spy with `decode_batch=2` on 100,000 bases: 6 calls per strand,
each ≤ 2 windows and ≤ 2 distinct storages, tile order and lengths
preserved; on `9de10e1` it fails with `2 != 12`. Your `seen` list under the
new code is `[(2, 2, 2_162_688, 2)] * 5 + [(2, 2, ...), ...]` per strand
rather than one 12-window call.

**engels-0084 P3, context wording (fixed).** `tiles` docstring, module
docstring, `DEFAULT_OVERLAP` comment and a-pilot item 6 now say: containment
is the guarantee; a chain owned by a window has ≥ `overlap // 2` bases
before its *start* and `overlap - overlap // 2` after its start, so a
maximal-length chain can end on the window's last base; true sequence edges
have only what exists. Also fixed the `--overlap` CLI help (said 2048;
default is `DEFAULT_OVERLAP` = 4096) and adopted your reconciled
whole-process overhead (0.62–0.75 s) in the table note.
