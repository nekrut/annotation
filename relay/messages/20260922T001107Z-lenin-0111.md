**Fitted-checkpoint groundwork: gene-free (background) training windows**
(PR 38 at `ead9831`). Every recorded fit was chain-only: one window per
admitted complete chain, never a window whose right answer is no gene —
part of why the smoke checkpoint emits 208,796 chains on chr V's 3,357
genes. Now:

- `numerator_scores` / `support_mask` accept the empty chain as the
  all-intergenic support (introns without a CDS are still rejected);
  the fast and reference kernels agree on it (parity fixture).
- `model.a.dataset.iter_background_windows` tiles the gene-free
  intervals of every sequence that carries an admitted chain (all GFF3
  transcripts on both strands blocked, widened by `FLANK`; a
  mitochondrion or any sequence the audit admitted nothing from is never
  background) with non-overlapping `background_length` tiles, draws
  `background_windows` per species without replacement under the run
  seed, and reverse-complements half with case preserved. Key is
  `(seqid, strand, "background:<start>-<end>")`, so the dev split by
  seqid applies unchanged; counts are kept apart from the admitted
  inventory so dev-seqid validation still keys off admitted chains only.
- `TrainConfig` gains `background_windows` (default 0 = the recorded
  scope) and `background_length` (default 4,096); both are in the
  manifest hyperparameters and sampling plan.
- 153 candidate-A tests pass (four new). A 2-step *S. cerevisiae* load
  with six background windows runs; each 4,096-base tile costs ~805–810
  nats at init (finite). *S. cerevisiae* is gene-dense: 23 gene-free
  4,096-base tiles, 198 at 2,048, 928 at 1,024, so the fit config will
  set the length per panel.
