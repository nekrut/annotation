## Segmentation and gene discovery have different input contracts

The [segmentation model card](https://huggingface.co/AIRI-Institute/genatator-caduceus-ps-multispecies-segmentation/blob/2716f2b2cdaf72c9cd2b4b8ed069f37314ada0a7/README.md) describes training on gene intervals, with one transcript per gene and no intergenic sequence. The [released dataset card](https://huggingface.co/datasets/AIRI-Institute/genatator-gene-segmentation-dataset/blob/3cf4012e0c31cc1af4a93bbc91df694710658523/README.md) retains all isoforms but provides `status == 1` for the representative: longest CDS for protein-coding genes, longest cumulative exon length for lncRNAs. These statements can coexist if training applies that filter; this tick did not verify the checkpoint's actual training invocation.

Parsing the card's assembly table yields 39 rows and 39 distinct accessions, including human `GCF_009914755.1`. It describes human chromosomes 8, 20 and 21 as excluded from training, with chromosome 20 used for final gene-level evaluation against all isoforms. **Inference:** this human test is a chromosome holdout, not an unseen-species experiment. Upstream foundation-model sequence exposure remains a separate unresolved provenance question. No Parquet dataset was downloaded to verify the card against its rows.

The [pipeline documentation](https://huggingface.co/AIRI-Institute/genatator-pipeline/blob/c23548864717b3df274cd8793c3af7670d5c42ef/README.md) adds interval discovery, transcript-type assignment, segmentation and GFF generation, and specifies CUDA/float32 execution. A crop-conditioned segmentation score should therefore remain separate from end-to-end gene-discovery accuracy and cost.

## The segmentation leaderboard is a recovery count, not genome-wide F1

In the pinned [metric implementation](https://huggingface.co/spaces/AIRI-Institute/genatator-ab-initio-segmentation-leaderboard/blob/f8305d479925f854df4d0c4466df921d83f1eeb1/gene_level_core.py), `_read_gff` assigns prediction IDs from `seqid`. Evaluation loops over reference transcripts, selects predictions with the matching transcript ID, and compares exact coordinate sets after converting the reference to transcript-relative coordinates. It compares exon and CDS sets separately. A successful isoform inserts its gene ID into a set, so repeated successful isoforms do not increase that gene's feature-specific count. Different isoforms can supply the exon and CDS successes.

Predictions whose IDs never match a reference transcript are not counted as false positives in this routine; it returns recovery counts and details, without a precision/F1 calculation. **Inference:** this interface evaluates segmentation of reference-associated intervals. It is not a chromosome-coordinate gene-matching evaluator.

The [leaderboard service](https://huggingface.co/spaces/AIRI-Institute/genatator-ab-initio-segmentation-leaderboard/blob/f8305d479925f854df4d0c4466df921d83f1eeb1/backend/leaderboard_service.py#L229) ranks the sum of recovered lncRNA exon structures, mRNA exon structures and mRNA CDS structures. That sum includes an endpoint outside the charter's initial scope and can credit a coding gene in both feature categories. Keep CDS recovery separately; do not relabel the aggregate as coding-gene F1. Full evaluator execution was not attempted.

## Default CDS output uses an exon-derived ORF heuristic

The pinned [configuration](https://huggingface.co/AIRI-Institute/genatator-pipeline/blob/c23548864717b3df274cd8793c3af7670d5c42ef/config.json) enables `use_cds_heuristic` and `splice_filter`. The active [wrapper branch](https://huggingface.co/AIRI-Institute/genatator-pipeline/blob/c23548864717b3df274cd8793c3af7670d5c42ef/genatator_pipeline.py#L737) uses that heuristic for mRNA, replacing the segmentation model's CDS intervals.

The [heuristic](https://huggingface.co/AIRI-Institute/genatator-pipeline/blob/c23548864717b3df274cd8793c3af7670d5c42ef/gff_utils.py#L80) concatenates predicted exonic bases in transcript orientation, translates all three frames using Biopython's default table, and selects the longest complete methionine-to-stop candidate. The resulting CDS mask includes the stop codon; absence of such a candidate produces an empty mask. **Inference:** checkpoint CDS logits alone do not specify the default output. Benchmarks must retain this option and normalize terminal-stop conventions; alternative genetic codes and incomplete genes require separate consideration. No ORF-accuracy claim follows from this source inspection.

## A reproduced splice-filter strand asymmetry

The [filter](https://huggingface.co/AIRI-Institute/genatator-pipeline/blob/c23548864717b3df274cd8793c3af7670d5c42ef/genatator_core.py#L1264) uses `LEFT_SET` unchanged at the genomic left boundary on the minus strand, while reverse-complementing its right-boundary set. The [caller](https://huggingface.co/AIRI-Institute/genatator-pipeline/blob/c23548864717b3df274cd8793c3af7670d5c42ef/genatator_pipeline.py#L643) supplies the reference-oriented interval and its strand separately.

An isolated execution extracted only the inspected constants and five pure-Python splice helpers through AST. For each donor/acceptor pair, the forward synthetic sequence was `AAA + donor + CC + acceptor + CCC + donor + CC + acceptor + AAA`; the minus case was its reverse complement. Both used zero-based, half-open exons `(0,3), (9,12), (18,21)`.

| Intron motif | Plus-strand retained exons | Minus-strand retained exons |
| --- | --- | --- |
| GT–AG | all three | all three |
| GC–AG | all three | terminal two only |
| AT–AC | all three | terminal two only |

Mapping the minus result back to forward coordinates confirms symmetry for the control and a mismatch for the latter cases. This establishes a local postprocessing asymmetry at the pinned revision, not its genomic frequency or effect on published scores. No full neural inference ran. Candidate recall should be measured by strand and splice class before importing this pipeline's results.
