## Published comparison: preserve inputs, training and denominators

The [final BRAKER3 paper](https://doi.org/10.1101/gr.278090.123), accessed through [Europe PMC XML](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC11216308/fullTextXML), evaluates eleven reference species using target-specific model training, repeat-masked genomes, and five or six RNA-seq libraries per species. Protein experiments distinguish target-species exclusion, target-order exclusion, and small manually selected sets of close relatives. These are different evidence conditions; order exclusion does not demonstrate a shared frozen model's transfer.

The MAKER2/Funannotate comparison retains eight species after failures on mouse, spider and zebrafish. MAKER2 uses distributed species models where available, otherwise SNAP/AUGUSTUS parameters trained on the evaluated reference annotation. Preserve this favorable training condition and the failed-run denominator.

Gene correctness permits any predicted isoform matching a reference transcript. Expression terciles use the prediction-input RNA-seq; mean transcript sensitivities are 23%, 55% and 76%, respectively. Runtime includes parameter training but excludes RNA alignment. MAKER2 timing additionally omits gene-finder training and transcriptome assembly. These conditions qualify the draft's aggregate accuracy and runtime claims; no new runtime measurement was made.

## Current evidence gate and an enforced-training exception

At the pinned [configuration](https://github.com/Gaius-Augustus/TSEBRA/blob/23ef2051650fbcc23db89044f16b57672fe66187/config/braker3.cfg), `intron_support=1.0` and `stasto_support=2`. The latter exceeds the fraction's ordinary range despite the configuration comment. [Feature construction](https://github.com/Gaius-Augustus/TSEBRA/blob/23ef2051650fbcc23db89044f16b57672fe66187/bin/features.py#L55) divides supported boundaries by two and assigns intron support one to transcripts without introns.

The [graph code](https://github.com/Gaius-Augustus/TSEBRA/blob/23ef2051650fbcc23db89044f16b57672fe66187/bin/overlap_graph.py#L292) accepts either support threshold, optionally rejects single-exon candidates with no boundary hint, and exempts enforced transcripts from removal. Thus, for ordinary complete transcripts, boundary hints cannot rescue partial intron support under this configuration. This is a configuration consequence, not an assertion of an unintended bug.

I extracted the inspected `relative_support`, evidence-gate conditionals, and singleton `decide_graph` path via Python AST. Source hashes were checked before execution. Synthetic objects supplied hint counts and enforcement flags; the original conditionals produced:

| Isolated candidate | Single-exon filter | Enforced | Retained |
| --- | --- | --- | --- |
| Both introns supported; neither boundary supported | off | no | yes |
| One of two introns supported; both boundaries supported | off | no | no |
| Same partially supported candidate | on | yes | yes |
| Single exon; neither boundary supported | off | no | yes |
| Single exon; neither boundary supported | on | no | no |
| Single exon; one boundary supported | on | no | yes |
| Single exon; neither boundary supported | on | yes | yes |

All seven expected outcomes passed. The harness omitted annotation parsing, numerical normalization, overlapping-candidate competition and full pipeline execution. It verifies the isolated gate and enforcement semantics, not genome-wide retention rates or prediction accuracy.

The pinned [BRAKER caller](https://github.com/Gaius-Augustus/BRAKER/blob/8f6a9b862c778f10ca33c27f931032bd7872b545/scripts/braker.pl#L9773) enforces `training.gtf` and adds the single-exon filter only when its genome-size value exceeds 300,000,000 bases. A benchmark should retain this automatic mode switch and identify whether a candidate came from the enforced set. **Design implication:** record candidate recall before evidence filtering, with unsupported introns and single-exon genes reported separately. The source inspection does not measure the switch's biological impact.

## Optional BUSCO mode changes the output

In the current [BRAKER launcher](https://github.com/Gaius-Augustus/BRAKER/blob/8f6a9b862c778f10ca33c27f931032bd7872b545/scripts/braker.pl#L148), `--busco_lineage` requests compleasm-derived hints and subsequent BUSCO-guided combination; the [active call](https://github.com/Gaius-Augustus/BRAKER/blob/8f6a9b862c778f10ca33c27f931032bd7872b545/scripts/braker.pl#L1572) invokes `best_by_compleasm` when that option is set. This is optional behavior in the inspected revision, not a claim about the original paper's runs.

The pinned [selection script](https://github.com/Gaius-Augustus/TSEBRA/blob/23ef2051650fbcc23db89044f16b57672fe66187/bin/best_by_compleasm.py#L500) compares missing-BUSCO percentages across component outputs. Depending on those values, it can add BUSCO-bearing transcripts to the BRAKER annotation or enforce a component gene set, then recombine and reassess. Its decision uses the configured missing-BUSCO and difference thresholds; the argument-parser description's five-percent wording does not fully describe the active branch. This was source inspection only.

**Benchmark implication:** record the lineage database/version and this option alongside code and component versions. If the same BUSCO family panel guides annotation, its subsequent completeness score is a selected endpoint, not independent validation. Retain a gene-structure reference comparison and distinguish this mode from runs without BUSCO-guided hints/selection.
