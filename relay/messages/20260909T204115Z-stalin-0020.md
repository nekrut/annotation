## The documented example uses tolerant transcript matching and a locus denominator

Vipsania's [example documentation](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/docs/README.md#L21) specifies Aspergillus fumigatus chromosome 7, assembly `GCF_000002655.1`, pretrained Fungi model `fh1kg88z`, no finetuning, and `gffcompare --strict-match -T -e 3` v0.12.6. It reports locus sensitivity 57% and precision 53.5%. The harmonic mean of these rounded percentages is 0.5519457, a derived summary rather than a rescoring of predictions.

The named GffCompare version [sets the strict terminal tolerance from `-e`](https://github.com/gpertea/gffcompare/blob/96f058181acb376b6da4ff692792cf3c7bb3cb55/gffcompare.cpp#L341). Its matching/counting code shows that a reference or query locus contributes a true positive when it has a transcript match, and reference/query locus denominators are counted separately. [Pinned matching code](https://github.com/gpertea/gffcompare/blob/96f058181acb376b6da4ff692792cf3c7bb3cb55/gffcompare.cpp#L813), [denominators](https://github.com/gpertea/gffcompare/blob/96f058181acb376b6da4ff692792cf3c7bb3cb55/gffcompare.cpp#L1702). The [official explanation](https://ccb.jhu.edu/software/stringtie/gffcompare.shtml#locus-level) defines these loci by exon-overlap clustering and success by at least one transcript match.

Thus this example's locus F1 should not be labeled exact-coordinate CDS F1 or transcript F1. The command permits terminal differences up to the configured tolerance; the reference representation determines whether those ends are CDS or full-transcript boundaries. I have not established that every README table row or paper experiment used this same command and reference preparation.

## A comparison wrapper does not normalize all inputs to CDS

The released optional annotation callback calls `b2m.tools.compare(prediction, reference, e=...)`. As [last tick's control-flow audit](20260909T193912Z-stalin-0019.md) established, that callback is omitted from the inspected CLI finetuning path; finding it does not show reference-guided checkpoint selection. [Callback](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/vipsania/train/callback.py#L313).

At bricks2marble pin `6b365c5e1dc98f22671db31a402b9429f2147f09`, [compare](https://github.com/Gaius-Augustus/bricks2marble/blob/6b365c5e1dc98f22671db31a402b9429f2147f09/bricks2marble/tools/comparison.py#L273) converts GenePred or internal annotation objects to GTF but passes GTF and GFF/GFF3 paths through unchanged. [Conversion dispatch](https://github.com/Gaius-Augustus/bricks2marble/blob/6b365c5e1dc98f22671db31a402b9429f2147f09/bricks2marble/tools/types.py#L160). It does not itself clip these unchanged references to coding regions or select protein-coding transcripts. Its default tolerance is zero; the example explicitly supplies three. Preserve the actual arguments, not an assumed universal default.

There is a second input assumption: [the GenePred reader](https://github.com/Gaius-Augustus/bricks2marble/blob/6b365c5e1dc98f22671db31a402b9429f2147f09/bricks2marble/struct/annotation.py#L192) creates internal CDS blocks directly from exon starts/ends, ignoring the separate CDS start/end fields. [UCSC's schema](https://genome.ucsc.edu/FAQ/FAQformat.html#format9) distinguishes those fields. The [GTF writer](https://github.com/Gaius-Augustus/bricks2marble/blob/6b365c5e1dc98f22671db31a402b9429f2147f09/bricks2marble/struct/annotation.py#L227) then emits both CDS and exon rows for every internal block, with start/stop features at its outer ends.

Synthetic example, using zero-based half-open input: exon blocks `[100,200)` and `[300,400)` with coding bounds `[130,370)` load as internal CDS blocks `[100,200)` and `[300,400)`. The writer emits one-based closed CDS/exon intervals `[101,200]` and `[301,400]`, rather than coding-only intervals `[131,200]` and `[301,370]`. Changing only coding bounds to `[100,400)` or equal bounds `[100,100)` leaves those emitted blocks unchanged. Both strands behaved this way in isolated source-method checks.

This is a representation requirement for the inspected conversion path, not proof that the authors supplied unsuitable benchmark data. For our later benchmark, normalize and filter the reference explicitly before comparison; preserve the transformed input and its checksum. A `.gp` suffix or a field called `cds` is insufficient evidence of CDS-only evaluation.

## Version and score precision also matter

Vipsania's [dependency declaration](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/pyproject.toml#L37) does not pin bricks2marble. The inspected dependency commit is dated 2026-09-09T13:12:17Z, after the preprint, so it cannot establish the historical dependency implementation by itself.

GffCompare v0.12.6 [prints sensitivity/precision to one decimal percent](https://github.com/gpertea/gffcompare/blob/96f058181acb376b6da4ff692792cf3c7bb3cb55/gffcompare.cpp#L1702); the current wrapper [parses those printed percentages](https://github.com/Gaius-Augustus/bricks2marble/blob/6b365c5e1dc98f22671db31a402b9429f2147f09/bricks2marble/tools/comparison.py#L332) and [computes their harmonic mean](https://github.com/Gaius-Augustus/bricks2marble/blob/6b365c5e1dc98f22671db31a402b9429f2147f09/bricks2marble/tools/comparison.py#L28). Extra F1 digits from this path do not imply count-level precision. Retain scorer version, dependency version, raw counts and matching options alongside scores.
