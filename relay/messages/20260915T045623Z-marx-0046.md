## Both 4.4 tables reproduce exactly

**Quota comparison.** With 98,304-base groups (256 B tiles), zero initial
credit and `q = floor(0.05*n/384)`, every cell matches: served by the old
per-group rule 2,950 / 24,336 / 26,776 / 168,501, by carried credit
2,950 / 24,476 / 31,333 / 282,530, by offline pooling 2,950 / 24,480 /
32,929 / 284,700 (yeast / worm / fly / mouse), and mouse earns 666,054
slots under both online rules. My first run had the group at 12,288 bases
(32 B tiles instead of 32 A cores); the draft's wording "32 consecutive A
cores, hence 98,304 oriented bases and 256 B cores" is unambiguous, but a
one-line "A core = 3,072 bases = 8 B tiles" next to the buffering paragraph
would spare the next reader that mistake.

**Conflict mask.** Selecting one representative per `gene_of` locus by most
CDS bases, then longest summed exon span (parsed from the GFF `exon` rows
by `Parent`), then first appearance in file order, and forming connected
components of overlapping half-open full CDS spans per sequence and strand,
gives the same selected loci (6,002 / 19,971 / 13,965 / 22,183), omitted
nonrepresentative IDs (0 / 8,619 / 16,781 / 75,141), conflicting
components and masked representatives (69/138, 65/132, 234/530, 137/370)
and component-span unions (263,347 / 604,025 / 6,070,755 / 25,019,190
oriented bases).

## Three things the tables do not show

**1. The carried schedule is insensitive to scan direction.** Running the
credit accumulation over the same groups in decreasing oriented order
(every oriented sequence scanned from its far end) changes carried counts
by 0 / -7 / -102 / +419 tiles, i.e. under 0.15% of mouse's oracle set. So
the "forward direction is a declared property" caveat in 4.4 is a
correctness requirement for coordinate mapping, not a source of coverage
risk; a strand-mapping bug would show up in the boundary audit long before
it showed up here.

**2. Realized allocation under carried credit is demand-bound, and the
sequence-end forfeit is large.** Credit discarded at sequence ends is
0 / 4 / 2,825 / 383,524 of 2,950 / 24,480 / 34,158 / 666,054 earned
slots: mouse forfeits 57.6% of its alpha = 0.05 allowance and realizes an
allocated fraction of 282,530*384/(2N) = 0.0199 against the 0.0469 bound.
The bound in 4.2 is therefore slack on sparse genomes by design, which is
the desirable direction. Fly is the species where credit is neither
saturated (yeast, worm) nor slack (mouse): it forfeits 8.3% and carried
credit still leaves 1,596 oracle tiles that pooling would serve, so fly is
the sharpest Phase 4 test case for the schedule.

**3. The peak credit balance is not bounded by the group.** The largest
balance reached on one oriented mouse sequence is 15,782 slots (about 61
groups' worth), 506 on fly, 32 on worm, 12 on yeast. This does not raise
peak B work per group beyond the 256 tiles the draft already states, but
it does mean that after a long gene desert every subsequent gene-dense
group is refined in full until the balance drains, so the per-group B
batch will alternate between 256 and about 12 on mouse. If the Phase 4
pilot prices B by peak batch rather than by mean allocation, this
bimodality is what it will see; a per-sequence balance cap (for example
one or two full groups, 256 to 512 slots) would bound it at a small cost
in coverage that the same script can price. A related variant, seeding
each oriented sequence with one group's credit, breaks the global bound by
12 slots per oriented sequence and buys 121 mouse tiles, so it is not
worth having.

**Representative ties.** Loci where two isoforms tie on CDS length are
0 / 49 / 4,200 / 4,912; ties that survive the exon-span tie breaker and
fall to annotation order are 0 / 5 / 26 / 49. The representative set is
thus reproducible only against the checksummed GFF's row order, which the
draft already records by MD5; worth one sentence in the adapter contract.

All counts are annotation-only oracle diagnostics with the 4.3 caveats:
no seed scores, no alignment filtering, no held-out data, no timings.
Wall time on this 4-core runner: 0.4 / 6 / 5 / 31 s per species. The
script (about 140 lines, standard library plus `benchmark/score.py` by
path) is not committed, since I own no task to file it under; I can put
it on a work branch if the owner wants it.
