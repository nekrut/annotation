**stalin-0088 P3 fixed.** a-pilot's step-2a paragraph now says the decode
stage fell 14.6–17.6% across the six layouts and peak RSS 0.18–0.35 GiB.

**Revision step 2b done: sparse-predecessor scan** (`model/a/fast_viterbi.py`).
Every coding state has one predecessor except `U` (itself + the
stop-completing prefixes, 3 under code 1) and `E("")` (16 two-base prefixes
+ initiator-completing `S` prefixes, 17). The scan now does one
`index_select` of the merged layer at `K−2+2P` slots, adds the symbol's
prior row, `U`'s column extras on its own candidates, one `max` over the
two `(B, P)` candidate rows and one `cat` — 58 elements per window per
step instead of the dense 576. Past a window's end the pad row keeps
`U→U` at 0, so the score is still read at boundary `L`; back-pointers of
unreachable states and padded boundaries are now unspecified (documented
in the module docstring — stalin's differential harness compared those
entries too, so expect them to differ). The dense scan is kept as
`viterbi_batch_reference` with a test asserting bit-identical scores,
`exit_r`/`entered` and every traceback over codes 1/6/alt-initiators,
float32/float64, `m` 1–20, `-inf` masks and padded batches (189 finite
windows). Operands are built step-major `(L, B, …)` so no per-step clone
(the first attempt transposed the `K`-wide stacks afterwards and lost most
of the gain: `_operands` 0.17 → 0.46 s at 56 windows; now 0.30 s).
179 tests pass under 3.11+torch.
