## The two that changed numbers

**Pseudogene and gene-fragment CDS rows were being scored as truth.** A
reference CDS row is not automatically a protein-coding gene. RefSeq
annotates pseudogenes with real CDS blocks carrying `pseudo=true`, and
immunoglobulin and T-cell receptor segments (`gene_biotype=V_segment`,
`D_segment`, `J_segment`, `C_region`) as gene fragments with no start or stop
codon of their own. Both are now dropped from truth and counted by reason,
and dropped from the *prediction* by the same test so an identity run is
still exactly 1.0; `--score-all-transcripts` restores the old behaviour.

The correction is larger and more species-specific than the yeast example
suggested. Counting only CDS-bearing transcripts on scored sequences:

| reference | dropped | of | why |
|---|---:|---:|---|
| *C. elegans* | 1,958 | 30,548 | pseudogene |
| human | 588 | 132,030 | 198 pseudogene, 390 gene fragments |
| *S. pombe* | 32 | 5,155 | pseudogene |
| *S. cerevisiae* | 6 | 6,008 | pseudogene |
| *A. thaliana*, maize, *Tetrahymena*, *P. falciparum*, *Nematostella* | 0 | | those references annotate pseudogenes without CDS rows |

6.4% of the *C. elegans* truth set was frameshifted pseudogene. Finding the
human gene fragments needed a second fix: the loader only followed
`mRNA`/`transcript` parents, so a CDS under a `V_gene_segment` had no path to
the gene row that says what it is.

**Partial CDS ends entered the start/stop denominators.** RefSeq marks an
incomplete CDS end with `start_range=` or `end_range=` on the CDS row, and
which *biological* end that is depends on the strand. A 5'-partial gene has
no annotated start codon, so the false negative is unavoidable by any
predictor. Both ends are now excluded independently. The half not asked for
but that the metric needs: dropping only the reference position moves the
charge to the predictor, whose own start somewhere inside that gene becomes a
false positive, so a predicted position inside the span of a reference
transcript partial at that end is dropped too — unless it coincides with a
surviving reference position, which is a real match. Read the CDS row, not
the mRNA: 788 of *S. pombe*'s 5,166 mRNA rows carry `partial=true`
(incomplete UTRs) against 6 of its CDS rows.

## The four documentation items

- `leakage_check.py` prints every training species tied at the deepest MRCA
  rank, truncated with a count. Chicken ties with *X. tropicalis* as well as
  mouse, and the frog is the closer relative in time; at Eukaryota all ten
  training species tie. §3.1 requotes the new output.
- §2.2 states that `cds_fraction_pct`'s denominator is the Datasets API's
  `genome_bp` and not the GFF's `##sequence-region` total, which also counts
  organelles. `annotation_stats.py` now emits
  `cds_fraction_of_sequence_region_pct` beside it so both are visible.
- §3.2's alignment rule is split, accepting marx's argument from
  `docs/data-sources.md` §7: jointly inferred alignments (Cactus, Ensembl
  EPO) must be rebuilt without the held-out species; reference-anchored ones
  (multiz) may have the row dropped at cut time, because that is a filter and
  not a realignment. This affects dm6 124-way (contains `apiMel4`) and mm39
  35-way (contains human). §3.3 gains a required `alignment_rows_dropped`
  key and `score.py` enforces it.
- §4.4 now says the matching is greedy and gives the tie-break (descending
  shared CDS bases, then reference id, then predicted id). "Optimal
  one-to-one" would make a second implementation of the spec disagree with
  this one, which §4 is otherwise careful to prevent.
