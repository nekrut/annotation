## Intron-position conservation is a supplied structural signal

GeMoMa translates coding exons from an annotated relative, searches the target with tblastn, and assembles compatible matches by dynamic programming while allowing intron gain/loss. Its original benchmark removes reference models with missing start/stop codons, internal stops or ambiguous bases and collapses identical CDSs. The extended reciprocal-hit evaluation takes the minimum nucleotide F1 across forward and reverse predictions; perfect reciprocal recovery therefore differs from ordinary whole-genome transcript sensitivity. The original studies set maximum intron length to 15 kb for plants and 200 kb for animals. [Keilwagen et al. (2016), Methods and Results, DOI 10.1093/nar/gkw092](https://pmc.ncbi.nlm.nih.gov/articles/PMC4872089/).

**My design inference:** conserved exon boundaries deserve an explicit comparative baseline, with reference annotations named as inputs. Test an ablation that removes those boundaries while retaining homologous proteins, and preserve a separate evaluation stratum for genes without usable reference homologs. A reference-annotation channel needs its own taxonomic and annotation-provenance controls alongside the whole-genome-alignment channel.

## Current search limits can depend on the reference transcript

Pinned Jstacs at `9d0c60cd7ecba5981a5953aa8e8674ddcdda3f6a`. The module identifies itself as version 1.9; this source inspection is separate from the older paper results. [Version constant](https://github.com/Jstacs/Jstacs/blob/9d0c60cd7ecba5981a5953aa8e8674ddcdda3f6a/projects/gemoma/GeMoMaModule.java#L39).

The default nominal maximum intron parameter is 15,000 and static mode is enabled. With static mode disabled, `maxAllowedIntron` becomes the reference transcript's maximum intron plus the user parameter. This is a finite, reference-conditioned search limit. It does not estimate an intron distribution from the target genome. Some candidate-connection checks multiply it by an intron-count factor; missing marginal-exon searches divide it by the reduction factor, whose default is 10. Consequently, a benchmark must retain the parameter combination and search stage instead of treating the nominal value as one uniform final-output ceiling. [Defaults](https://github.com/Jstacs/Jstacs/blob/9d0c60cd7ecba5981a5953aa8e8674ddcdda3f6a/projects/gemoma/GeMoMa.java#L4791), [reference-conditioned assignment](https://github.com/Jstacs/Jstacs/blob/9d0c60cd7ecba5981a5953aa8e8674ddcdda3f6a/projects/gemoma/GeMoMa.java#L2270), [connection check](https://github.com/Jstacs/Jstacs/blob/9d0c60cd7ecba5981a5953aa8e8674ddcdda3f6a/projects/gemoma/GeMoMa.java#L2925), [marginal search](https://github.com/Jstacs/Jstacs/blob/9d0c60cd7ecba5981a5953aa8e8674ddcdda3f6a/projects/gemoma/GeMoMa.java#L3591).

The current Extractor defaults also select full-length transcripts, discard premature stops, remove ambiguous transcripts via its EXCEPTION policy, and assume the CDS contains the stop codon. These are declared input policies to log before counting available reference genes. [Extractor parameters](https://github.com/Jstacs/Jstacs/blob/9d0c60cd7ecba5981a5953aa8e8674ddcdda3f6a/projects/gemoma/Extractor.java#L1294). No compiled predictor or extractor was run.
