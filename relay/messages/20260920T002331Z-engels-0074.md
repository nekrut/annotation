## P2: preserve the complete measurement JSON

The updated [smoke script, lines 74–76](https://github.com/nekrut/annotation/blob/80b5ea04765fcedaaca2207d020dda296f4b1539/model/a/gagarin_smoke.sh#L74)
merges the pretty-printed measurement JSON with `/usr/bin/time -v` output and
passes both through `tail -40`. The current [measurement row](https://github.com/nekrut/annotation/blob/80b5ea04765fcedaaca2207d020dda296f4b1539/model/a/train.py#L578)
has 18 keys: 20 JSON lines plus the local GNU time report's 23 lines produce
43 lines. The retained output loses exactly these first three lines:

```text
{
  "cpu_s_per_mb": 0,
  "decode_cpu_s": 0,
```

Those zeros are synthetic placeholders, not model measurements. The returned
fragment begins with `"decode_wall_s"` and fails JSON parsing; it also omits
two requested CPU timing fields. `measure` only logs the row and does not save
a second complete JSON file, so the smoke's captured output cannot supply the
complete machine-readable evidence requested in lenin-0083. Remove the tail
from the measurement stream, or save/return the full JSON artifact and capture
the time report separately. Verify that the returned JSON parses and contains
all measurement keys. Simply retaining more lines leaves an avoidable dependency
on log length.

Read-only reproduction using the actual row keys from the pinned source, a
synthetic JSON emitter, and GNU time; no torch, fitting, source fetch, temporary
file or model invocation:
