## Vipsania: distinguish unsupervised adaptation from frozen transfer

[Krieg et al., preprint DOI](https://doi.org/10.64898/2026.08.26.747235). The [bioRxiv API](https://api.biorxiv.org/details/biorxiv/10.64898/2026.08.26.747235) identifies v1, posted 2026-08-30, CC BY, with no journal publication recorded. Full-text HTML could not be opened through the browser tool; the v1 PDF returned HTTP 403. The following implementation findings come from the repository, not a claimed full-paper reading.

The [pinned README](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/README.md) describes masked-nucleotide training with an internal HMM, clade-specific pretrained models, and optional target-genome finetuning. Its recommended annotation command uses `--finetune`. Absence of annotation supervision therefore does not imply a single fixed pan-eukaryotic checkpoint, or absence of target-sequence exposure.

The [training documentation](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/docs/training.md) explicitly offers nominal 2M, 10M and 25M configurations and says released checkpoints use the 25M variant. The [2M configuration](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/configs/base_2M.json) has six layers, hidden width 150, linear recurrent/FFN/HMM blocks, and initial intron lengths `[100, 10000]`. These are configuration values, not measured realized parameter count or achieved accuracy. A small parameter budget alone is consequently insufficient as a novelty claim. The training guide also exposes start/stop-codon and splice-pattern configuration: support for alternative genetic codes should be distinguished from automatic discovery of the correct code.

I parsed the pinned [test manifest](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/docs/test_species.tsv) and [training manifest](https://github.com/Gaius-Augustus/Vipsania/blob/0c5f84a261def7736c5349af8064869ce432353d/docs/training_species.tsv) in memory with Python's `csv.DictReader(delimiter="\t")`. The test file contains 266 rows forming 133 unique `(model_id, assembly_accession)` pairs across 18 model IDs; each pair has exactly one pretrained and one finetuned row. The training file has 1,692 rows. Exact intersection of the unique model/accession tuples finds 75 test pairs in the corresponding training lists. No accession-version normalization was applied. This is sequence exposure in a documented unsupervised protocol, not evidence of annotation-label leakage; it cannot by itself establish performance on wholly unseen genomes.

Arithmetic means of the published per-species `locus_f1` values reproduce the rounded README examples:

| Manifest clade | Paired assemblies | Pretrained mean | Finetuned mean |
| --- | ---: | ---: | ---: |
| Arthropoda | 6 | 0.21725 | 0.20690 |
| Vertebrata | 13 | 0.32698 | 0.40578 |

These are recomputed summaries of author-reported scores, not independently rerun predictions. The arthropod result shows adaptation is not uniformly beneficial. Exact locus-matching rules, isoform treatment, reference quality, and adaptation time remain unverified. Future benchmarking should report frozen inference, prior sequence exposure, and target adaptation separately, charging adaptation compute to the latter.

## OrionGeno: inspect what phylogenetic conditioning means

[Liu et al., preprint DOI](https://doi.org/10.64898/2026.04.26.720859). The [bioRxiv API](https://api.biorxiv.org/details/biorxiv/10.64898/2026.04.26.720859) returns v1 dated 2026-04-29 and v2 dated 2026-08-24, with different titles and CC BY-NC-ND metadata; no journal publication is recorded. The pinned README still cites the v1 title. The v2 PDF returned HTTP 403, so paper-level architecture and accuracy claims remain pending.

The [README](https://github.com/BGIResearch/OrionGeno/blob/37559f68e9ca84568757b5ffd059086d6b4540e6/README.md) requires a genome FASTA and a selected lineage checkpoint; species conditioning is optional and does not choose the checkpoint. In [eval_model_class.py](https://github.com/BGIResearch/OrionGeno/blob/37559f68e9ca84568757b5ffd059086d6b4540e6/oriongeno/eval_model_class.py#L249), the supplied species name selects a vector from a packaged dictionary; an unknown supplied name raises `KeyError`, while omitting a name uses no species vector. [species_conditioning.py](https://github.com/BGIResearch/OrionGeno/blob/37559f68e9ca84568757b5ffd059086d6b4540e6/oriongeno/model_packages/orion_geno/species_conditioning.py) detaches that vector before conditioning. [modeling_orion_geno.py](https://github.com/BGIResearch/OrionGeno/blob/37559f68e9ca84568757b5ffd059086d6b4540e6/oriongeno/model_packages/orion_geno/modeling_orion_geno.py#L360) passes it through the sequence encoder/decoder around a state-space backbone.

My inference from this inspected inference path: species-vector conditioning is a relevant comparator for the charter's geometry hypothesis, but does not establish implementation of a locus-specific taxon-by-site alignment encoder or Tree-RoPE. The training provenance and geometric construction of the packaged vectors still need primary-text verification. I did not deserialize the pickle or execute downloaded source.

The [gene benchmark page](https://github.com/BGIResearch/OrionGeno/blob/37559f68e9ca84568757b5ffd059086d6b4540e6/docs/benchmark/gene_benchmark.md) labels a 36-species, 16-group panel. I inspected its table structure and selected rows, but do not import its rankings: exact endpoint definitions, comparator checkpoint choices and splits are unresolved.
