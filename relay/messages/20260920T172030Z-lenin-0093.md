T-human-014 tick summary (PR 38 at 28c5339; a-pilot.md section 3.2; artifacts
`relay/artifacts/T-human-014/smoke-local-20260920/{fast-kernel,measure-chrI}/`).

**Fast delayed-entry training kernel implemented and checked.** `model/a/fast_loss.py`
computes the same `log Z - log Z_num` as the reference torch forward with the
delayed-entry recurrence on dense tensors: a (B, 24) coding layer, (B, 24, R) tails,
donors parked and entered exactly m boundaries later with an `unfold` window sum, the
per-base (K, K) transition stack as one `einsum` over a fixed channel-coefficient tensor
plus an IUPAC-indexed prior table. `-inf` is floored at -1e30 so infeasible supports give
`+inf` loss rather than NaN gradients. `tests/test_a_fast_loss.py` (8 cases) pins parity
with `torch_loss.py` to <= 1e-9 in partition, loss and emission gradient on the
section-3.4 fixtures, 30 random lattices (IUPAC ambiguity, tables 1 and 6, m 1-4, R 1-3,
sparse -inf masks) and batched-vs-single; suite is 141/141.

**Cost, like for like (one thread, float64, same four yeast windows as 3.1):** linear at
~0.2 CPU-s/kb forward+backward; the 11,255-base window takes 2.3 s and 1.08 GB against the
reference's 81.7 s and 9.0 GB (35x faster, 8x less memory). The 20-step smoke fit rerun
with `loss_kernel: fast` reproduces the reference's NLL trajectory exactly
(0.0001 / 0.0006) in 1 min 32 s and 0.97 GB (was 12 min 50 s, 7.15 GB) and in 24.7 CPU-s
on one pinned core (was 1,635 CPU-s). `train.py` now defaults to the fast kernel; the
reference stays selectable for parity runs and the choice is recorded in the manifest.
A note for reviewers: the first draft indexed the transition stack per step inside the
scan, which makes torch's backward quadratic in window length; `unbind` once fixed it.

**One-core `measure` on yeast chromosome I** (94 windows, 143,653 oriented bases, taskset
to one core): featurizer 3.6 + encoder 2.7 CPU-s/Mb are inside the 15 CPU-s/Mb budget; the
pure-Python `DelayedEntryDecoder.viterbi` costs 66 CPU-s/Mb and is the failing stage. The
tensor scan in max-product mode with back-pointers replaces it next tick before any
section-5 chromosome row is filled. GPU half still needs gagarin (lenin-0083 open).

Compute: local CPU ~0.5 CPU-h on the unmetered dev host; cluster 0 CPU-h, 0 GPU-h; no
