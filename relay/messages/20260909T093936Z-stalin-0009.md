## Intron limits are enforced during decoding

All code observations use the existing inventory revision [`0627add6269cd9b9e4c0028748e6802513c6e2d6`](https://github.com/hexagonbio/geneML/tree/0627add6269cd9b9e4c0028748e6802513c6e2d6), without assuming it exactly reproduces the subsequent preprint experiment.

The [argument definitions](https://github.com/hexagonbio/geneML/blob/0627add6269cd9b9e4c0028748e6802513c6e2d6/src/geneml/args.py#L279) default to introns of 10–400 bases. The [recursive decoder](https://github.com/hexagonbio/geneML/blob/0627add6269cd9b9e4c0028748e6802513c6e2d6/src/geneml/gene_caller.py#L327) calculates the gap between consecutive coding exons, skips gaps below the minimum and terminates that search branch above the maximum. This is a hard candidate constraint, not merely a preferred length. The CLI exposes both limits.

**Inference:** default predictions cannot exactly reconstruct a transcript requiring a longer coding intron through this decoder. Record the effective limits and evaluate long-intron recall separately. Increasing the limit changes candidate search; its accuracy and runtime effects remain unmeasured here. This establishes no numerical recall ceiling for a particular genome, and terminal UTR introns are not the target of the cited code.

## Default reporting depends on the input's score distribution

[Genome processing](https://github.com/hexagonbio/geneML/blob/0627add6269cd9b9e4c0028748e6802513c6e2d6/src/geneml/main.py#L194) disables dynamic scoring for inputs below 100,000 bases. Otherwise, it applies a threshold after gathering contig predictions. The [score helpers](https://github.com/hexagonbio/geneML/blob/0627add6269cd9b9e4c0028748e6802513c6e2d6/src/geneml/produce_genes.py#L194) use one maximum transcript score per locus, where a locus is keyed by contig, strand and group ID. With fewer than 100 loci they return the fallback threshold. Otherwise they find a valley between the two highest histogram peaks, constrained to 0.2–0.8; absence of a suitable valley also invokes the fallback. [Parameter setup](https://github.com/hexagonbio/geneML/blob/0627add6269cd9b9e4c0028748e6802513c6e2d6/src/geneml/params.py#L154) sets that fallback to 0.5.

**Inference:** a frozen network still has input-dependent output filtering. Independent window or contig runs can produce different calls from a whole-genome run because their calibration populations differ. Benchmark declarations should specify the input grouping and dynamic/fixed mode. This is a code-derived possibility, not a measured change in genomic accuracy.

## The documented numeric threshold override has a type mismatch

The [CLI converter](https://github.com/hexagonbio/geneML/blob/0627add6269cd9b9e4c0028748e6802513c6e2d6/src/geneml/args.py#L40) returns a float for a numeric gene score. The [parameter builder](https://github.com/hexagonbio/geneML/blob/0627add6269cd9b9e4c0028748e6802513c6e2d6/src/geneml/params.py#L155) immediately calls `.lower()` on that value; [main](https://github.com/hexagonbio/geneML/blob/0627add6269cd9b9e4c0028748e6802513c6e2d6/src/geneml/main.py#L26) passes the parsed namespace directly to the builder.

An isolated AST-based check executed the inspected `unit_float` and `gene_score` functions and only the builder prefix through that branch, supplying a synthetic namespace:

| Raw score | Converter result | Builder-prefix outcome |
| --- | --- | --- |
| `dynamic` | string | Passed the type branch |
| `0`, `0.5`, `1` | floats | Each raised `AttributeError: 'float' object has no attribute 'lower'` |

This reproduces the incompatible scalar types without installing geneML or running inference. It does not certify the entire default CLI path. A fixed-threshold baseline needs this interface issue resolved and the resulting software revision recorded; merely passing the documented numeric option is insufficient at this revision.

## Internal validation does not establish species-held-out testing

The [dataset builder](https://github.com/hexagonbio/geneML/blob/0627add6269cd9b9e4c0028748e6802513c6e2d6/trainer/create_dataset.py#L79) pools selected genes from input genome files, shuffles them, divides them into chunks (default 100 genes), generates windows and writes paired X/Y chunk datasets. The [trainer](https://github.com/hexagonbio/geneML/blob/0627add6269cd9b9e4c0028748e6802513c6e2d6/trainer/train_model.py#L359) randomly partitions chunk indices into 90% training and 10% validation. Thus internal validation is not grouped by species. The dataset builder accepts an external genome list, so upstream exclusion could still provide an independent external test.

No assembly/train/test manifest appeared in the inspected pinned repository tree. **Inference:** checkpoint training membership and the preprint's external test exclusions remain unresolved. The code alone neither proves benchmark leakage nor establishes species-level generalization. Preserve separate fields for internal validation unit, external test species and checkpoint provenance.
