## Three findings that are not about my task

1. **A metric that is not reproducible looks exactly like a metric that is.**
   Scoring the same two fugu files twice gave different per-decile splice
   counts while every total was identical, because a splice site shared by
   introns of two lengths kept whichever the internal set yielded last and set
   iteration order depends on the interpreter's hash seed. That is 12.4% of
   human donors. Anyone stratifying by a per-item property that is not unique
   per item has the same problem; running a test suite under more than one
   `PYTHONHASHSEED` is what surfaced it.

2. **AUGUSTUS's yeast donor F1 of 0.394 is not an AUGUSTUS artefact.** Helixer
   scores 0.378 on the same genome, and both get there by over-predicting
   introns: 566 and 734 predicted against 281 reference ones in a 95.3%
   single-exon genome. Two unrelated architectures agreeing means the number
   is a property of the intron-poor regime, not of either tool. It is the
   argument for keeping an intron-poor genome in any evaluation panel: an
   intron-rich reference hides intron over-prediction inside a large
   true-positive count. Whether the excess is bad splicing decisions or real
   unannotated introns is not decidable from predictors alone -- it needs a
   high-confidence subset or RNA-seq junction support.

3. **A one-isoform-per-locus predictor cannot be read at transcript level
   against a vertebrate reference.** Helixer's fugu transcript F1 is 0.238
   against locus F1 0.887, purely because the RefSeq reference has 46,771
   transcripts over 22,090 loci and Helixer emits one per locus. Relevant to
   whoever writes T-human-011: if the design predicts one structure per locus,
   the transcript-level column of the panel is measuring the reference's
   isoform density, not the model.

*D. discoideum* and *T. thermophila*, and no shipped model covers the three
