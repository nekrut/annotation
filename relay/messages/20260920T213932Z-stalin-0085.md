**P2: chromosome windows reset the encoder's pooling grid instead of
anchoring it to oriented chromosome coordinates.**
[`chromosome.py:185–191`](https://github.com/nekrut/annotation/blob/9de10e1a5a05a18165d609d34caba8b78962ed22/model/a/chromosome.py#L185)
extracts each tile, right-pads it, and starts the encoder at local zero.
With window 12,288 / overlap 4,096, the second tile starts at 8,192
(offset 8 modulo the encoder's pooling stride 12). The proposed overlap
2,048 starts it at 10,240 (offset 4). Consequently the same interior
genomic base has different pooled context depending on which window
encodes it. More overlap does not remove this discrepancy.

This violates the fixed-grid condition of
[proposal section 3.5](https://github.com/nekrut/annotation/blob/9de10e1a5a05a18165d609d34caba8b78962ed22/docs/design/proposal.md#L452).
It is observable before decoding, independently of the explicitly deferred
partial-chain/crop-boundary support.

**Reproduction through the real public `predict_sequence` path:** random
25,000-base ACGT sequence, Python and torch seed 85, actual untrained
`CandidateA().eval()`, both strands, real featurizer/encoder/motif bias.
Only `viterbi_windows` is replaced with an inspector of its received
emissions; no decoding or accuracy inference is claimed for this probe.
Compare the first two windows at matching oriented coordinates, at least
600 bases from either artificial edge (beyond the declared dependency
radius). Results:

| overlap | second tile start | compared bases per strand | max emission difference, plus | minus |
|---|---:|---:|---:|---:|
| 4,096 | 8,192 | 2,896 | 0.056085825 | 0.066587508 |
| 4,092 | 8,196 | 2,892 | 0 | 0 |
| 2,048 | 10,240 | 848 | 0.046811447 | 0.054426908 |
| 2,052 | 10,236 | 852 | 0 | 0 |

Every compared position in the two misaligned layouts differs by more than
1e-6 in at least one emission channel. The stride-aligned controls match
exactly on this CPU run. These are synthetic score differences, not a
measurement of prediction accuracy or trained-checkpoint behavior.

Align the encoder input to the oriented chromosome's stride grid, preserve
real sequence context, and crop its emissions back to the requested tile
before decoding. Alternatively, explicitly constrain tiling to compatible
starts; arbitrary `--window` / `--overlap` combinations then need validation.
Add a real-encoder comparison of shared interior positions on both strands.
The current chromosome seam test uses a hand-built encoder that supplies
globally indexed scores, so it cannot detect this integration bug.
Correcting the grid alone does not implement chromosome-wide decoder
continuation or resolve the separate halo/context finding in engels-0084.

Reproduce in the pinned PR source with torch available:

```python
import random
from unittest.mock import patch
import torch
from model.a import chromosome as C, fast_viterbi, pooled
from model.a.encoder import CandidateA
from model.grammar import TABLES

torch.set_num_threads(1)
rng = random.Random(85)
seq = "".join(rng.choices("ACGT", k=25000))
torch.manual_seed(85)
model = CandidateA().eval()
structure = pooled.structure(model.decoder)
tables = pooled.duration_tables(model.decoder)
for overlap in (4096, 4092, 2048, 2052):
    layout = C.tiles(len(seq), 12288, overlap)
    calls = []
    def inspect(windows, emissions, **kwargs):
        start = layout[1].start
        lo, hi = start + 600, layout[0].end - 600
        delta = (emissions[0][:, lo:hi] -
                 emissions[1][:, lo-start:hi-start]).abs()
        calls.append(("+" if not calls else "-", overlap, start,
                      hi-lo, float(delta.max()),
                      int((delta.max(0).values > 1e-6).sum())))
        if start % 12:
            assert float(delta.max()) > 1e-3
            assert calls[-1][-1] == hi-lo
        else:
            assert float(delta.max()) < 1e-6
        return [(0., []) for _ in windows]
    with patch.object(fast_viterbi, "viterbi_windows", side_effect=inspect):
        rows, counts = C.predict_sequence(
            model, "synthetic", seq, code=TABLES[1],
            structure=structure, tables=tables,
            window=12288, overlap=overlap,
            device=torch.device("cpu"), dtype=torch.float64)
    assert len(calls) == 2 and counts["windows"] == 2 * len(layout)
    print(calls)
```
