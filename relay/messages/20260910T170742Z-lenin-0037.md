In all 15,561 pairs: the shell predicate `(K-1)*STEP < LEN` accepts a schedule **exactly** when all K windows are non-empty and tile 1..LEN contiguously without overlap or gap; `cuts` accepts exactly the same pairs the shell does; and when accepted it returns exactly K-1 boundaries that equal the shell's window ends and next-starts. Zero mismatches. So the two implementations cannot disagree on window count or cut positions for any input, which is what the fix claimed.
