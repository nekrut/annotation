## A submission with more isoforms than the reference

Every scored run so far emits at most one transcript per locus, so the §4.4
branch that charges an *unmatched extra prediction* as a false positive had
only ever run on fixtures. GENCODE 50 (Ensembl 116, primary-assembly GFF3,
sha256 `272f9972...`) scored against the human RefSeq reference is the input
that exercises it: 370,476 scored chains against the reference's 131,442, on
the same assembly. Preparation was sequence renaming only, from the GRCh38.p14
assembly report; 423 rows of 11.25M sit on two scaffolds the report does not
map and were dropped. 64 s, 1.6 GB, identical under `PYTHONHASHSEED` 0 and 1.

This is **not** an accuracy measurement — both files are human curation of the
same genome — but it is a real multi-isoform input, and it is the shape an
evidence-based pipeline produces.

|---|---|---|---|---|---|---|---|
| 0.933 | 0.698 | 0.908 | 0.826 | **0.290** | 0.968 | 0.637 | 0.360 |

Transcript precision 0.190 against sensitivity 0.610 is what §4.4 does to a
submission offering 2.8 isoforms for every one the reference has; locus F1
0.968 on the same run is the contrast the two levels exist for. Stop-codon
precision 0.231 and terminal-exon F1 0.340 are the 91,818
nonsense-mediated-decay transcripts, each ending at a stop RefSeq does not
annotate as one.

## Two defects, both invisible to a RefSeq-shaped submission

1. **The §4 biotype filter read only `gene_biotype`.** GENCODE writes
   `gene_type`, Ensembl writes `biotype`. The filter is applied to the
   prediction as well as the reference, so reading one spelling dropped the
   reference's 390 immunoglobulin and T-cell receptor transcripts as
   unanswerable while keeping GENCODE's 421 and charging them as false
   positives — the submission was penalised for answering a question §4
   forbids the reference to ask. All three spellings are now read. Locus F1
   0.959 -> 0.968 (false-positive loci 1,133 -> 723), nucleotide 0.931 ->
   0.933.
2. **`predicted_transcripts_not_scored` pooled two unrelated causes.** It was
   every predicted transcript minus the scored ones, so biotype-dropped rows
   landed in the field whose documented meaning is "on a sequence the
   reference does not have" and whose warning tells the submitter to check
   their sequence names. It read 434 where 13 are actually off-panel. It now
   counts sequence exclusion only.

Verified: self-test 111 -> 118 checks, all passing under `PYTHONHASHSEED`
0/1/42; the new fixture fails on the pre-fix code with locus fp 2 and
transcript fp 4. All six earlier validation runs have
`predicted_transcript_selection.dropped == 0`, so none of them moves.

## One observation worth passing on

GENCODE states 257,153 distinct CDS acceptors against 212,078 donors, 21%
more, where RefSeq states 193,359 against 188,913, 2.4% more. Recounted
independently from the GFF3 outside the scorer, both figures agree exactly, so
acceptor F1 0.826 sitting well below donor F1 0.908 is annotation depth and
not a scoring artefact. **For T-human-011:** a model scored against a
deeply annotated reference meets a 3' splice-site decision surface that is
materially richer than the 5' one, and §4.3 reporting the two separately is
what makes that visible. **For T-human-008 (marx):** the isoform-policy
sidecar matters for the same reason — a `longest-cds` training target throws
away most of that acceptor diversity.
