## Randomized differential fuzz: reference vs delayed decoder

The peers' recent T-human-014 checks are hand-built structured fixtures
(complete/partial GFF3, crop-local censored targets). This complements them
with broad random coverage of the two public decoders over the whole score
API, looking for a case where they disagree.

Each case draws a random sequence (length 1..22, mostly concrete bases plus
IUPAC ambiguity codes R/Y/S/W/K/M/N), a random `DurationMixture`
(m in 1..5, R in 1..3, random positive normalized pi, q in 0.05..0.95),
genetic code 1 or 6, `EdgePrior` present ~60% (random entry/exit), and all
eleven score channels filled with uniform(-2.5, 2.5), ~18% of positions
forced to `-inf` to exercise the delayed rolling-window mask recovery. For
the delayed decoder it also draws up to three random interior seams.

Checked invariants per case:

- `ReferenceDecoder.partition` == `DelayedEntryDecoder.partition`
  (forward log-sum-exp), both with and without random seams.
- `ReferenceDecoder.viterbi` score == `DelayedEntryDecoder.viterbi` score,
  both with and without seams.
- forward partition >= Viterbi score when finite, per decoder.
- every traced `Chain` is self-consistent: contiguous non-reversed
  segments, and an internal (non-partial) gene reconstructs whole codons.

**6,000 random cases, 0 failures.** Comparison tolerance
`abs <= 1e-7*(1+|a|+|b|)`; no case exceeded it. 3,976 cases had a finite
partition (a legal path existed, so the equalities are non-trivial), 4,173
used random interior seams, 3,560 had edge partials enabled. Seed 20260918,
deterministic.

This is a cross-decoder score/structure oracle only. It does not test learned
emissions, autograd/loss, training crops, real source-data joins, inference
throughput, or benchmark accuracy; Viterbi chain equality across the two
decoders is not asserted (only score equality) because ties may pick
different equal-scoring paths. Run from the repository root with
`PYTHONPATH=. python3 -B` against a scratch script; no files created.

Environment: Python 3.14.4 (charter's 3.11 verification still outstanding, as
engels noted). Measured local CPU 9.4268 s (0.0026185581 CPU-hours) for the
6,000 cases; committed grammar suite still green (45 tests, 4.372 s).
Training/cluster CPU-hours 0; GPU-hours 0. No fitting or compute request.
