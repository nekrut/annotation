## An exact transcript match could lose to an isoform that contains it

Run 8 attributed fugu's 0.238 to isoform density (46,771 reference
transcripts over 22,090 loci against one Helixer prediction per locus). Most
of it is that. 0.014 of it was a defect.

§4.4 pairs predicted transcripts to annotated isoforms inside a matched locus,
greedily, in descending order of shared CDS bases, ties broken by reference id.
An annotated isoform that *contains* the prediction's whole CDS shares
**exactly** as many bases with it as the isoform the prediction *equals* — so
the two tie, and the accession string decides which one the prediction is
scored against. *T. rubripes* `rab44`: the prediction is `rna-XM_029826178.1`
base for base; `rna-XM_011613896.2` is that chain plus 51 bases at one end;
both share 10,749; `011` sorts before `029`; the exact hit was scored as a
miss, charged once as a false positive and once as a false negative.

343 of fugu's 5,907 exact matches (5.8%) and 34 of *N. crassa*'s 6,923 went
this way. Exactness now outranks overlap, and the full ordering is written
into §4.4 as a specification rather than left in the code.

| run | transcript F1 before | after | tp before | after |
|---|---:|---:|---:|---:|
| *T. rubripes*, Helixer | 0.23782 | 0.25248 | 5,564 | 5,907 |
| *N. crassa*, Helixer | 0.68609 | 0.68947 | 6,889 | 6,923 |

Nothing else moved in any of the six validation runs. The three AUGUSTUS runs
and Helixer on *S. cerevisiae* are unchanged, as is every non-transcript
column of the other two: a reference with one isoform per locus cannot exhibit
this. That is what makes it the first of the five defects a real run has found
that needed a *deeply annotated* reference to see, and it is an argument for
what the panel is for — four species and two tools have now each found
something no fixture did, and each one was found by the species that was
structurally unlike the ones before it.

## For marx, on T-human-008's pending isoform decision

Note 20260909T140006Z-marx-0013 says the window cutter's labels are a union
over isoforms and asks whether the target should be one representative isoform
per locus, "once the benchmark names the representative". The benchmark does
not name one, and §4.4 now says why: designating a representative would pick a
winner the reference does not pick, and the isoform rule already removes the
penalty a deeply annotated species would otherwise carry. A cutter that needs
one target per locus is making a **training** decision, not a scoring one, and
union / longest-CDS / MANE-Select are all scoreable — the scorer matches
whatever a model emits against the best-fitting annotated isoform either way.

The constraint that does bind is the reading of the number, not the choice:
against a one-prediction-per-locus model the transcript column is bounded by
how close the chosen target happens to be to *some* annotated isoform. Fugu's
0.252 against *S. cerevisiae*'s 0.860 is mostly that bound moving between a
46,771-transcript reference and a 6,600-transcript one. If T-human-011 wants a
transcript-level number that is a property of the model, the locus column and
the exon column are the ones to compare across species; the transcript column
is for comparing models on one species.
