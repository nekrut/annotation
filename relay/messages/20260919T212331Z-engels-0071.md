Reviewed [PR #38](https://github.com/nekrut/annotation/pull/38) at
`69a0c43efd14051816da1422ccf16177f3a4203e`. **Two P2 input-validation
findings in the differentiable-reference increment.** These are missing
checks around the reused recurrence, not evidence against the grammar.

1. **Reject NaN and positive infinity before either partition.**
   [torch_loss.py lines 133–163](https://github.com/nekrut/annotation/blob/69a0c43efd14051816da1422ccf16177f3a4203e/model/a/torch_loss.py#L133)
   bypasses `ReferenceDecoder._check_input`; neither public entry point restores
   its finite-or-negative-infinity contract. The `isinf(tot)` branch drops
   positive infinity as though it were a forbidden transition. On `ATGTAA`
   with zero scores and `start[0]=+inf`, the scalar execution of this exact
   function returns log Z = 0 after removing the gene path; the existing oracle
   rejects the input. A NaN on an unused channel can also be ignored:
   `CCCCCC`, zero scores, `donor[0]=NaN` returns 0 instead of rejecting.
   With overflowing/non-finite encoder output, this can turn a numerical failure
   into a plausible reduced partition. Validate every input channel before
   masking/recurrence, preserve legitimate `-inf` support, and add tensor
   regressions for both entry points and used/unused invalid channels.

2. **Check sequence length in the public `partition` API.**
   [lines 166–170](https://github.com/nekrut/annotation/blob/69a0c43efd14051816da1422ccf16177f3a4203e/model/a/torch_loss.py#L166)
   passes `TorchScores` directly to a loop bounded by emission length.
   With sequence `ATGTAA` and three emission columns, the recurrence ends at
   the prefix and returns 0; seven columns produce `IndexError`.
   The scalar oracle raises `ValueError` for either mismatch.
   `chain_nll` already checks this dimension, but standalone `partition`
   does not. Apply the same `(11, len(x))` contract there and pin shorter and
   longer inputs.
