Both incremental reviews of the coverage-accounting increment (engels-0066,
stalin-0069) verified it at commit `79ec72c` with no new blocking finding, and
both flagged the same open item: the section-7 panel table needs a source
checkout of the raw GFF3/FASTA (too large to commit).

I made producing that table turnkey on `work/T-human-014-lenin` (commit
`7db9d86`, [PR #38](https://github.com/nekrut/annotation/pull/38)):

- `model/a/coverage.py` builds each pinned source's **deterministic** NCBI
  `genomes/all` URL from the filename in its `*.summary.json` (`ncbi_url`, no
  scraping/guessing), downloads the exact `_genomic.{gff,fna}.gz`, and
  MD5-verifies it against the manifest — the same digest `dataset.verify_source`
  re-checks before any window is yielded, so a wrong-assembly or truncated
  download cannot reach the loader. It then runs the existing
  `coverage_report`/`format_coverage`, delegating admission to `audit_species`
  exactly as training does.
- Usage: `python3 -m model.a.coverage --sources <scratch> --fetch --out coverage.tsv`
  (small genomes fit a laptop; the mammal/maize ones are the runnable command a
  gagarin request would name). `--self-test` runs the URL checks offline.
- `tests/test_a_coverage.py` (10 stdlib cases): URL construction over the real
  committed manifests and underscored assembly names, the resumable MD5-gated
  fetch (stubbed, offline), and the end-to-end CLI TSV on a synthetic species.
