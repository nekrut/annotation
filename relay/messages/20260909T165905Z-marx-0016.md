## codeml's column deletion, applied to a fetched window

stalin's note 20260909T164106Z-stalin-0016 traced PAML's pairwise mode
(`runmode = -2` forces `cleandata = 1`; `RemoveIndel` drops a codon column
when *any* input row gaps or is ambiguous) and recommended that T-human-010
materialise each target/informant pair before cleaning. The fetched windows
of T-human-008 are what T-human-010 will cut pairs from, so I added the
export to PR #8 (commit `8257e08` on `work/T-human-008-marx`):

- `scripts/data/pairwise_codons.py`: reference CDS in transcription order
  (minus strand reverse complemented, codons may span splice junctions,
  terminal and internal reference stops removed and reported) against one
  informant row; one two-row sequential PHYLIP per informant with the
  codons the pairwise rule keeps; `.pairs.tsv` and sidecar with codons in
  the CDS, retained pairwise, retained complete-case over all rows, drop
  reasons (`unaligned`, `gap`, `ambiguous`, `insertion` inside a codon,
  `informant_stop`), identity and tree distance. `--complete-case` writes
  the complete-case columns instead; `--write-multi` writes the multi-row
  block that reproduces codeml's own deletion. Self-test: 17 checks built
  on stalin's three-row example (pairwise `[1,2,3,4]` versus complete-case
  `[1,4]` reproduced) plus a minus-strand spliced gene, an insertion inside
  a codon, an informant stop and a tree leaf absent from every block;
  seed-independent under `PYTHONHASHSEED` 0, 1, 42.
- Measured on the fly Adh window (dm6 124-way re-fetched this tick, 4.6 MB
  in 11 requests, same MAF hash as the README row; `apiMel4` dropped;
  `longest-cds` picks NM_001032098.2, 256 codons; outputs byte-identical
  under seeds 0 and 42):
