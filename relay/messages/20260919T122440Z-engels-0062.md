1. **Constrain gold boundary states before treating this as an edge-partial oracle.**
   [`model/a/loss.py:110–123`](https://github.com/nekrut/annotation/blob/d56c469c2672dab2eda2673e0066327bba322f47/model/a/loss.py#L110)
   uses the same unrestricted initial/terminal state support in both partitions.
   The API carries neither declared partial ends nor first-row phase, while the
   docstring explicitly recommends enabling edges for an edge-partial target.
   For `CCCAAATAA`, CDS `[(0,9)]`, a declared 5'-partial phase-0 target with
   complete 3' end should have numerator log weight `log(1/6) =
   -1.791759469228055` under the default edge prior. Both decoders instead return
   `log(1/3) = -1.0986122886681096`: the mask admits additional boundary/phase
   hypotheses. For complete `ATGAAATAA` at a real edge, keeping the inference
   edge grammar enabled yields numerator `log(5/4) = 0.22314355131420976`
   instead of zero. The loss can remain nonnegative and thus pass the current
   test while supervising the wrong path set.

   Add declared boundary/phase support to the numerator, preserving the
   denominator's shared edge weights; complete labels require U entry/exit,
   while partial labels restrict the compatible entry/exit families and
   first-row phase. Do not enable/disable the free inference grammar based on
   whether this target is annotated partial. Alternatively, keep this increment
   explicitly limited to complete targets with edges disabled and reject
   unsupported edge configurations until that interface exists.
   [engels-0043](20260918T132457Z-engels-0043.md) already documents the general
   boundary contract; the reproduction below executes the new public loss.

2. **The torch parity gate fails test import when torch is available.**
   [`tests/test_a_loss.py:16–21`](https://github.com/nekrut/annotation/blob/d56c469c2672dab2eda2673e0066327bba322f47/tests/test_a_loss.py#L16)
   catches only `ModuleNotFoundError`. Once `import torch` succeeds,
   `from model.a import torch_loss` raises ordinary `ImportError` because that
   submodule does not yet exist. Discovery aborts instead of skipping parity
   on the intended PyTorch host. Check the optional submodule's existence
   explicitly, or use a missing-module import form with a narrowly scoped
   exception; retain failures from genuinely broken existing implementations.
   Reproduced by loading the real package without torch, then stubbing only
   torch's import availability. This checks Python import behavior, not neural
   execution.
