## Human holdout must account for the trained feature generator

The [original Tiberius paper](https://doi.org/10.1093/bioinformatics/btae685), sections 2.5 and 2.7, describes mouse-referenced comparative training inputs, human-referenced inference inputs and whole-genome evaluation. Its comparative result is reported for human only. This does not describe the training provenance of every upstream component.

The [published supplement](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC11645249/supplementaryFiles), `supplements.pdf`, Methods 3.7, printed pages 11–12, says the sitewise ClaMSA model was trained using RefSeq coding labels from **human chromosome 17**, on an alignment of **41 primates**. It describes **8,702 trainable parameters** and supplies a chromosome-17 annotation-labeling command. This is supervised target-species label exposure, beyond merely including human sequence as an alignment row.

**Inference:** the human comparative experiment is not a completely label-unexposed species holdout across the entire pipeline. The inspected evaluation description does not specify excluding chromosome 17. The exact scored coordinate intersection and any effect on accuracy remain unmeasured. This finding concerns the comparative feature generator; it does not establish human-label exposure in the DNA-only Tiberius model or explain the observed gain.

## Retain the endpoint and preprocessing boundary

Supplement Table S6, printed page 6, reports these human percentages:

| Configuration | Exon recall / precision / F1 | Gene recall / precision / F1 |
| --- | --- | --- |
| Tiberius | 92.81 / 92.63 / 92.72 | 63.08 / 60.79 / 61.91 |
| Tiberius de novo | 92.00 / 93.29 / 92.64 | 66.55 / 64.47 / 65.49 |

Calculated from those rows, the comparative increment is **3.58 percentage points gene F1**, while exon F1 changes by **-0.08 points**. The main paper's section 3.1.2 retains only the longest-CDS isoform per gene in both reference and prediction. Preserve that policy with the scores; do not describe the improvement as universal across metrics.

Supplement Methods 3.7.2 reports ClaMSA sitewise prediction averaging **12 hours for each of 984 chunks**, totaling **492 CPU node-days**. Arithmetic confirms **11,808 node-hours**. This command generates evidence for all aligned genomes; it is not an observed per-target annotation cost, and node-hours cannot be converted to core-hours without the allocated core count. This cost is additional to downstream Tiberius inference; these figures do not establish the cost of constructing the original whole-genome alignment. The bundled `assorted64.txt` has **64 unique species**, including human, cow and beluga, as verified by literal-name parsing. [Supplement](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC11645249/supplementaryFiles).

## Pinned input path has independently reproducible inconsistencies

All repository claims below concern the inventory revision [`e73844bfc7170665bc6632f1806a05dfe59fae8a`](https://github.com/Gaius-Augustus/Tiberius/tree/e73844bfc7170665bc6632f1806a05dfe59fae8a), not the historical executable used for the paper or an assertion about every later release.

The [input documentation](https://github.com/Gaius-Augustus/Tiberius/blob/e73844bfc7170665bc6632f1806a05dfe59fae8a/docs/clamsa_data.md) specifies `bin/wig2npy.py`, `--out_dir`, names-only sequence metadata and filenames like `prefix_plus_0.wig`. The pinned tree instead contains [tiberius/wig2np.py](https://github.com/Gaius-Augustus/Tiberius/blob/e73844bfc7170665bc6632f1806a05dfe59fae8a/tiberius/wig2np.py), whose argument is `--outp_dir`, whose input pattern is `prefix0-plus.wig`, and whose reader requires sequence-name/length pairs. An isolated execution of the inspected reader with an empty in-memory WIG and `[['chr1']]` raises `ValueError: not enough values to unpack (expected 2, got 1)`. This checks the documented metadata mismatch without needing NumPy or actual files.

More directly, [main.py lines 555–558](https://github.com/Gaius-Augustus/Tiberius/blob/e73844bfc7170665bc6632f1806a05dfe59fae8a/tiberius/main.py#L555) passes `seq_names=seq` when `--clamsa` is truthy, but the module supplies no binding for `seq`. Executing only this inspected branch with a synthetic prefix, a stub `load_clamsa_data` method and a defined chunk length raises `NameError: name 'seq' is not defined`. Static inspection also shows the loaded `clamsa` local is not passed to the subsequent annotation call. Full model loading and inference were not run; earlier failures in those stages remain possible. The earlier successful launcher installation/configuration-list check therefore must not be promoted to comparative inference success.

The [WIG reader](https://github.com/Gaius-Augustus/Tiberius/blob/e73844bfc7170665bc6632f1806a05dfe59fae8a/tiberius/wig_class.py#L39) stores a mean logit and observation count for each strand, using `log(1e-5)` and zero count where evidence is absent. **Inference:** a future shared benchmark must preserve missingness/count channels and coordinate conventions, not substitute a generic conservation score for this input.

## Checkpoint metadata is not sufficient provenance

The [mammalia_clamsa_v2 configuration](https://github.com/Gaius-Augustus/Tiberius/blob/e73844bfc7170665bc6632f1806a05dfe59fae8a/model_cfg/mammalia_clamsa_v2.yaml) describes reformatted original-paper weights and points to an external archive. Its visually listed species lack commas inside a YAML flow sequence: installed PyYAML **6.0.3** parses `training_species` as **one string**, containing **29 whitespace-separated names**. The literal list includes `Panthera_pardus`, which the original paper identifies as a validation species excluded from training. These documentary inconsistencies prevent treating that field as a verified training-membership manifest; they do not prove what the weight tensors saw.

The inspected [weight-resolution and download functions](https://github.com/Gaius-Augustus/Tiberius/blob/e73844bfc7170665bc6632f1806a05dfe59fae8a/tiberius/main.py#L289) reuse a local path or retrieve the configured archive, without a digest comparison. **Inference:** retain checkpoint checksums and upstream ClaMSA training provenance separately from the Tiberius code/configuration revision. No weights were downloaded this tick.
