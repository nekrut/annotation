Reviewed the new chromosome 21 commit in [PR #20](https://github.com/nekrut/annotation/pull/20), pinned at `781df39a3aad0cd410b779599b66f2e5e994df62`. **Recommendation: correct failure handling in the new runner and qualify the new causal/extrapolation claims before acceptance.** This is a bounded review of the new row and its interpretation, not a fresh audit of the earlier literature or measurements.

## Requested corrections

1. **A failed window currently becomes a successful partial run.** In the pinned [window runner](https://github.com/nekrut/annotation/blob/781df39a3aad0cd410b779599b66f2e5e994df62/docs/cost-baseline/run_augustus_windows.sh#L10), only `set -u` is enabled. The `xargs` return status at lines 24–25 is not checked; lines 26–35 concatenate whatever predictions exist, sum available time records, and end with `cat run.log`. If AUGUSTUS exits unsuccessfully for one window, the wrapper can still return success and expose a partial GFF as the completed chromosome run. The summary also never checks GNU time's recorded exit statuses. Make worker failure terminate the wrapper before publishing the combined GFF and success summary; check that each scheduled window completed successfully. Preserve legitimate successful windows with no gene features when handling `grep` statuses. Apply equivalent failure propagation to setup/input errors. This is a code-path finding, not evidence that the reported measurement itself suffered a worker failure. A compact per-window completion/timing record would make the claimed successful run auditable without committing genome data.

2. **Seven cuts do not establish a seven-locus error bound.** The new [discussion](https://github.com/nekrut/annotation/blob/781df39a3aad0cd410b779599b66f2e5e994df62/docs/cost-baseline.md#L303) says at most seven reference loci lie on a boundary, then uses that to dismiss windowing as an explanation for the accuracy gap. The [runner](https://github.com/nekrut/annotation/blob/781df39a3aad0cd410b779599b66f2e5e994df62/docs/cost-baseline/run_augustus_windows.sh#L18) establishes seven internal cut positions, not how many distinct reference loci intersect them. Overlapping loci can share a cut, and forcing complete models separately in each window can change predictions near a cut as well as models directly crossing it. If the reference-locus count was measured, retain the exact cut coordinates, reference-filter definition and resulting count; otherwise remove the asserted bound. Keep the accuracy explicitly scoped to this windowed invocation, and frame intron-length decoding as a hypothesis to test. No additional whole-chromosome run is necessary to make that wording correction.

3. **Keep the new interpretations conditional on the measured setting.** In [section 3.3](https://github.com/nekrut/annotation/blob/781df39a3aad0cd410b779599b66f2e5e994df62/docs/cost-baseline.md#L284), the observed spread between AUGUSTUS runs is transferred directly to the future model, reference-locus density is treated as evidence of the number of candidate exons scored internally, and different sequence/parameter combinations are used to attribute a memory ratio to the parameter set. Those mechanisms are not isolated by the reported comparisons. The masking control supports a statement about the tested window, not every chromosome. Label these explanations as hypotheses and retain the measured observations separately. Likewise, the whole-human estimate in [section 5.2](https://github.com/nekrut/annotation/blob/781df39a3aad0cd410b779599b66f2e5e994df62/docs/cost-baseline.md#L465) should explicitly say it assumes every megabase costs the same as this windowed chromosome 21 run. Comparing that extrapolation with a published wall-time-times-thread-count bound does not measure thread occupancy in the published run; remove the claim that its threads were mostly idle.
