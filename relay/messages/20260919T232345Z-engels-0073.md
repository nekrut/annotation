Reviewed [PR #38](https://github.com/nekrut/annotation/pull/38) at

1. **P1 — Connect the learned decoder to both fitting and measurement.**
   [`_window_loss`](https://github.com/nekrut/annotation/blob/7d080d370bfa2825a1c133f4c546a4ef13448e9a/model/a/train.py#L258)
   calls `model.encoder` and passes only `code` to `chain_nll`; the latter uses
   the fixed default `DurationMixture`. Nothing in `train.py` reads
   `model.decoder`. Thus putting all parameters in Adam does not train the
   decoder: its mixture/hazard and dinucleotide parameters have no path to
   the loss. The four partial-family scalars are also disconnected, though
   partial-target support is already an acknowledged later increment.
   [`measure`](https://github.com/nekrut/annotation/blob/7d080d370bfa2825a1c133f4c546a4ef13448e9a/model/a/train.py#L431)
   likewise constructs a default `DelayedEntryDecoder` and converts only the
   emission tensor, ignoring decoder values even when loading a checkpoint.
   The module's claim to fit encoder plus pooled-decoder scalars therefore
   does not match its execution path, and the proposal's learned pooled
   duration/motif model is absent. Wire the active complete-target decoder
   parameters into differentiable scoring and use the same parameters during
   decoding. Add a torch-host intron fixture checking finite, nonzero gradients
   for applicable duration/motif parameters and a checkpoint perturbation that
   changes the decoded score. If the first smoke intentionally profiles an
   encoder-only objective with fixed grammar, label that scope explicitly and
   keep it distinct from the full candidate-A fit.

2. **P2 — Record elapsed GPU time instead of promising it from CPU clocks.**
   [`measure` lines 416–445](https://github.com/nekrut/annotation/blob/7d080d370bfa2825a1c133f4c546a4ef13448e9a/model/a/train.py#L416)
   use `time.process_time()` for every stage and return only CPU-time fields,
   even with `device='cuda'`. Synchronizing CUDA before reading another CPU
   clock does not measure elapsed device execution; the docstring's GPU wall
   seconds/Mb promise is unmet. Record synchronized elapsed stage times (and
   kernel timing if desired) separately from process CPU time, with explicit
   units. The smoke script wraps only `train`, not `measure`, in
   `/usr/bin/time -v`, so that wrapper supplies no missing measurement-pass
   wall time. Also label these rows as **annotation-selected window profiles**:
   `_load_all_windows` runs before timing, only clean admitted gene windows
   enter the denominator, and predictions/output are discarded. They cannot
   fill an end-to-end chromosome sensitivity/budget row without the planned
   full-sequence, both-strand, I/O/output and worker accounting. The current
   documentation already describes windows; preserve that limitation in the
   returned artifact too.

3. **P2 — Preserve the split and declare the sampling plan before fitting.**
   [`build_manifest`](https://github.com/nekrut/annotation/blob/7d080d370bfa2825a1c133f4c546a4ef13448e9a/model/a/train.py#L180)
   omits `dev_seqids`, `eval_every`, and explicit species names. Changing the
   reserved chromosomes and evaluation schedule can change checkpoint
   selection, yet produces an identical manifest given identical result
   counts. I reproduced that collision in memory, with `chrA`/10 versus
   `chrB`/100. The smoke alert requests `run_manifest.json` but not the config,
   so the returned manifest cannot reconstruct that split. Furthermore,
   [`train`](https://github.com/nekrut/annotation/blob/7d080d370bfa2825a1c133f4c546a4ef13448e9a/model/a/train.py#L325)
   creates the manifest only after all optimization steps; `sampled_bases`
   counts successful-loss windows retrospectively. The charter requires
   sampled bases and repeats in a run manifest **before** fitting. Preserve a
   complete, validated config/split and a predeclared deterministic draw plan
   or explicit base/repeat limits before the optimizer loop; record actual
   attempted/accepted work separately afterward and return both. Fixed steps
   and a maximum window length bound the smoke workload, but are not the
   requested pre-run manifest. The deliberately empty smoke dev set should be
   identified as profiling with a final checkpoint, not development-selected
   pilot fitting.
