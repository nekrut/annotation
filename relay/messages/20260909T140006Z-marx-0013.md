## Seed audit of the T-human-008 scripts

Ran `cut_windows.py`, `fetch_window.py`, `coverage_by_distance.py` and
`tree_composition.py` under `PYTHONHASHSEED` 0, 1, 2 and 42 on the fly `Adh`
124-way window (re-fetched three times: byte-identical MAF, tree and
annotation, manifests differing only in the timestamp). Tables from the
aggregator and the tree script were identical across seeds. None of the four
depends on set iteration order: everything derived from a set is sorted
before it reaches an output, and the dicts are insertion-ordered.

The cutter's archives did differ across runs, and the cause was not the seed
but wall-clock zip timestamps in the `.npz` members (2-second resolution, so
a run straddling a boundary changes the bytes while every array payload is
identical). A checksum of an example meant nothing. Members now carry a
fixed timestamp; four seeds give one checksum set.

## A labelling defect the audit surfaced

Reading `paint_labels` for order dependence found a real bug instead: every
base of all four `Adh` examples carried strand -1, including the 3,331 CDS
bases of the plus-strand `Adh` gene, because the minus-strand gene that
spans the whole window is listed first in the annotation and the strand
channel was first-writer, while frames and boundary marks were counted on
the plus strand. Any nested gene (common in the fly, and the intronic genes
of large vertebrate loci) had contradictory channels. The rule is now: a
base belongs to the transcript giving it its highest label class (CDS > UTR
> intron), ties to the shortest span, then the first in annotation order;
strand and frame are the owner's. Section 6.3 of `docs/data-sources.md`
states it. Self-test 28 -> 35 (nested opposite-strand gene, its reverse
complement, byte-identical repeated runs); commit 4228a15 on
`work/T-human-008-marx`, PR #8 description updated.

## For T-human-011, from lenin's third finding

The cutter's labels are a union over isoforms, so an example's target is not
any one transcript's structure where isoforms differ. A model trained on it
learns the union, and the benchmark's transcript-level column then measures
the reference's isoform density, as lenin saw for Helixer on fugu. Whether
the target should be one representative isoform per locus is a design
decision; the cutter can take it as a `--transcript-types` list once the
benchmark names the representative. Section 6.3 now says so.
