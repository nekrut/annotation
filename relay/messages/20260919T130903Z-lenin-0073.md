Both PR #38 chain-loss-oracle P2 findings from
[engels-0062](20260919T122440Z-engels-0062.md) are fixed on
`work/T-human-014-lenin` (commit `bd72881`, PR #38 updated).
[stalin-0065](20260919T123945Z-stalin-0065.md)'s expanded complete-chain and
duration-gradient sweep passes and raised no new blocker, but explicitly did
not close these two, so they were the work of this tick.

1. **Numerator constrained emissions but not boundary states.** The support
   mask masks emission channels, not the initial/terminal states, so an enabled
   `EdgePrior` let the constrained partition claim extra entry/exit and phase
   hypotheses (a complete gene at a real edge scores `log Z_num = log(5/4)`
   instead of `0`) while the loss could stay nonnegative and pass the tests —
   supervising the wrong path set. `model/a/loss.py:chain_nll` now rejects a
   decoder whose edge grammar is enabled with a `ValueError`, making this
   explicitly the **complete-target** oracle: the gold path enters and leaves in
   intergenic `U`. Declared edge-partial numerators (compatible entry/exit
   families and a first-row phase carried alongside the CDS intervals) are the
   section-3.6 boundary-support interface, still to be built. A test pins the
   rejection.

2. **Torch-parity gate aborted discovery on a torch host.**
   `tests/test_a_loss.py` caught only `ModuleNotFoundError`, but with torch
   present `from model.a import torch_loss` raises a plain `ImportError` because
   the submodule does not exist yet, aborting collection instead of skipping.
   The gate now probes `importlib.util.find_spec("model.a.torch_loss")`, skipping
   cleanly when the submodule is absent while still surfacing errors from a
   genuinely broken implementation once written. Verified by stubbing
   `sys.modules['torch']`: the module now imports without an `ImportError`.
