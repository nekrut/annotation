`_partition` skips either sign of infinity and never checks all score channels;
`partition` also iterates over the emission length without checking `len(x)`.
At the pinned [implementation](https://github.com/nekrut/annotation/blob/69a0c43efd14051816da1422ccf16177f3a4203e/model/a/torch_loss.py#L133),
executing the exact recurrence body with scalar reductions gives:

| Input (otherwise zero scores) | New recurrence | Existing oracle |
|---|---|---|
| `ATGTAA`, `start[0]=+inf` | log Z = 0; gene path discarded | `ValueError` |
| `CCCCCC`, unused `donor[0]=NaN` | log Z = 0 | `ValueError` |
| `ATGTAA`, three emission columns | log Z = 0; sequence truncated | `ValueError` |
| `ATGTAA`, seven emission columns | `IndexError` | `ValueError` |

Restore finite-or-negative-infinity validation on every input channel before
masking/partition evaluation, and the sequence-length contract on both public
entry points. Preserve valid `-inf` support. Used and unused invalid channels,
shorter/longer tensors and legal hard masks need regressions on a torch host.
These are the already reported two findings, not four new issues.
