Two P3 clarifications before collecting the final measurements:

1. **CPU affinity does not enforce completion or an idle core.** The
   [scoring README](../artifacts/T-human-014/smoke-local-20260920/fit-cpu-v3/score-final/README.md)
   says that pinning the launcher to the fit's core means it runs only
   after the fit exits successfully. The launcher contains no wait,
   completion-status check or lock; `taskset` sets affinity and another
   process can run on that same CPU immediately. A file-free check below
   reproduced this locally. State this as an operator precondition, and
   record the fit's successful completion before launching scoring (or
   add an explicit gate). CPU pinning alone also does not establish the
   idle-core condition for the cost comparison. This is a run-order
   claim in the prepared procedure, not evidence that scoring has already
   overlapped the fit or that a reported measurement is invalid.

2. **Preregistration is before final checkpoint selection, not necessarily
   before any checkpoint exists.** The parent
   [v3 README](../artifacts/T-human-014/smoke-local-20260920/fit-cpu-v3/README.md)
   and lenin-0125 say the inputs were committed before the checkpoint
   exists. In the pinned
   [training loop](https://github.com/nekrut/annotation/blob/6c7aac1/model/a/train.py#L717),
   every improving development evaluation immediately calls
   `torch.save(..., "best.pt")`; writing is not deferred until fit exit.
   The ongoing run therefore does not establish absence of an interim
   checkpoint. Use "before fit completion and final checkpoint selection,
   and before v3 chromosome scoring". That preserves the supported
   preregistration claim without asserting that an interim model could
   not exist. I did not inspect the live checkpoint or process.

Affinity reproduction (in memory; the children block on stdin and do no
model work):

```python
import os, subprocess, sys
core = max(os.sched_getaffinity(0))
cmd = ['taskset', '-c', str(core), sys.executable, '-c',
       'import sys; print("ready", flush=True); sys.stdin.readline()']
a = subprocess.Popen(cmd, stdin=subprocess.PIPE,
                     stdout=subprocess.PIPE, text=True)
b = None
try:
    assert a.stdout.readline().strip() == 'ready'
    b = subprocess.Popen(cmd, stdin=subprocess.PIPE,
                         stdout=subprocess.PIPE, text=True)
    assert b.stdout.readline().strip() == 'ready'
    assert a.poll() is None and b.poll() is None
finally:
    for p in (a, b):
        if p is not None:
            p.communicate('\n', timeout=5)
            assert p.returncode == 0
```

Both children were alive on the same selected CPU when checked. This
checks affinity semantics, not the pilot host's contention or idle state.
