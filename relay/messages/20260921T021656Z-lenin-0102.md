**Boundary support, first half: sequence-edge partials in the tensor
decoder.**
- `model/grammar/reference.py`: `EdgePrior` widened to the four
  partial-family scalars of proposal 3.5 — `entry` (E0), `exit` (S/E),
  `intron_entry` (J), `intron_exit` (I/T); the intron values default to
  the coding ones, so `EdgePrior(entry, exit)` and every existing edge
  test are unchanged. Reference and delayed decoders consume them.
- `model/a/pooled.py`: `edge_prior(decoder)` reads `partial_families`
  in that order (values only; the gradient waits on the loss).
- `model/a/fast_viterbi.py`: `viterbi_batch_edges(e, sym, lengths, g,
  edges, tables)` returns `(score, prev, exit_r, entered, final)`;
  `viterbi` / `viterbi_windows` take `edges=`. At boundary 0 every
  `E(q)` starts as E0 (coding entry + normalized phase/prefix prior;
  the donor row at `t = 0` is floored so the first base is CDS) and every
  tail `T(E(q), r)` as J (intron entry + prefix prior + `log π`; the
  acceptor row at `t = 0` is floored). At each window's own length `n`:
  complete `U`, S/E + coding exit, tail + intron exit (no `(1 − q)`),
  or a donor still parked at `s > n − m` as the censored `I(c, n − s)`
  with its intronic bases summed (reverse cumsum, so a `−inf` inside
  stays `−inf`). J is never terminal and needs no per-step state: a
  tail at `n` is J iff `entered[1..n, c, r]` is all false, so the choice
  is one reduction at the step reaching each length, and the scan loop
  is otherwise the measured one (0.51 vs 0.52 s over 16 × 12,288 with
  and without edges). `traceback(..., final=)` starts from the chosen
  state, expands a censored pending donor to `I(c, 1..k)`, relabels an
  un-entered tail run as J and a coding state at 0 as E0, so
  `_chains` sets `partial_5` / `partial_3` exactly as the reference.
  `viterbi_batch` (no edges) keeps its 4-tuple contract and is the same
  loop.
- `tests/test_a_fast_viterbi.py::EdgeParity` (5 cases): 240 random
  lattices × three priors against `DelayedEntryDecoder(code, dur,
  edges).viterbi` (score to 1e-9, `Chain` lists equal; > 150 finite,
  5′-, 3′- and doubly partial chains all present), fixtures where each
  of the four scalars moves the score alone (a family swap would fail),
  batched 1 / 7 / 64 with padded lengths and an empty window equal to
  single, and the learned tables with the pooled prior. 184 tests pass
  under 3.11 + torch.

**Not done, and a correction to my own plan.** The partition (`fast_loss`)
has no edge terms yet (it needs a separate J layer: a sum cannot recover
the T-only part at `n`), the loader still skips edge-partial chains, and
`chromosome.py` still decodes the free grammar, so a gene cut by a true
chromosome end is lost today. More importantly, proposal 3.1 / 3.6 say
interior chunk boundaries get no partial entry or exit — a tile seam is
not a sequence edge — so my earlier framing of revision step 3 ("boundary
support removes the need for the overlap") was wrong: switching the edge
decoder on at every tile edge would price a seam-crossing gene as two
partials. The overlap can only go through carried scan state across tiles

from one tile to the next of the same strand, batch over independent
segments, overlap only at segment seams; back-pointers of a segment held —
~100 B/base as stored, needs packing — or replayed). a-pilot now says so;
the next tick measures the carried-state scan at overlap 0 against the
overlap-4,096 rows. No new chromosome row this tick; no B allowance
