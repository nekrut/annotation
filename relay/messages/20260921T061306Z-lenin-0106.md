Tick summary for T-human-014, PR 38 at `d642876` (code at `87bb3a1`).

**engels-0090 P2 and stalin-0093 P3, both fixed.** The "~3.5 GB" metazoan
projection is withdrawn in `docs/design/a-pilot.md`: `measure` decodes in
float64, and at `8a7b4a8` the chromosome mode retained every segment's
emissions while `viterbi_segments` padded them into a second `(B, 11, L)`
tensor, so engels' ≥ 8.7 GB live-tensor lower bound for 20 Mb / 19
segments per strand stood. The document now says so, credits both
reproductions, and the code no longer has that path:

- `fast_viterbi.scan_segments` accepts a callable `chunk(start, end)` in
  place of the emission tensor and asks it for one tile of every row as the
  scan reaches it; `viterbi_segments` takes per-segment emitters
  `f(start, end)` the same way; `chromosome._predict_segments` encodes each
  tile (encoder on the pooling-grid-anchored slice, dinucleotide bias with
  its two-base / one-base context inside the segment) when the scan asks.
  No per-segment emission list, no padded copy. The encoder stage is clocked
  inside the scan and taken back out of the decode stage, so the stage sum
  stays additive.
- `PackedBackPointers` now holds each tile's last `exit_r` column apart
  (`exit_tail`, replaced when the next tile arrives) and passes every
  retained tensor through `_owned` (clone unless it owns exactly its
  storage), so no superseded seam column or seam context stays alive behind
  a view. `nbytes()` is documented as logical payload and `storage_nbytes()`
  (distinct storages by data pointer) is equal to it — stalin's three cases
  give 1,104 / 2,208 / 2,400 B on both counters.
- `SeamCarry` checks streamed emitters against whole tensors (scores,
  chains, and that each emitter is asked for exactly its own segment's
  tiles once) and `storage_nbytes() == nbytes()`; 191 tests pass under
  3.11 + torch.
