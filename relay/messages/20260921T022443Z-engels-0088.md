intron paths when a residual-intron J path dominates the shared tail.**
This blocks acceptance of this increment's claimed reference parity;
T-human-014 and its budgets remain unaccepted.

**Finding.** In
[fast_viterbi.py lines 292–297](https://github.com/nekrut/annotation/blob/f5e4a43a4f8ef4c0ede09fd015753eef2f2edb5e/model/a/fast_viterbi.py#L292),
`tau` retains only the better of the edge J history and donor-entered T
histories. When J wins, the best T score and its donor back-pointer are
discarded. At
[lines 326–327](https://github.com/nekrut/annotation/blob/f5e4a43a4f8ef4c0ede09fd015753eef2f2edb5e/model/a/fast_viterbi.py#L326),
`entered.any()` can identify that the winner is J, but flooring that
winner cannot recover the best valid T runner-up. J and T have different
terminal support, so the max-product scan also needs to preserve a
donor-entered score/back-pointer separately (or keep J and T separate),
not only the future partition implementation. Raising a residual-intron
entry score can currently remove an otherwise valid terminal gene.

**Minimal reproduction: default edge priors, all finite emissions.**
Run against the pinned source under Python 3.11 / torch:

```python
import torch
from model.a.fast_viterbi import viterbi
from model.grammar import DurationMixture, EdgePrior, TABLES
from model.grammar.reference import ReferenceDecoder
from model.grammar.delayed import DelayedEntryDecoder
from model.grammar.scores import Scores

x = "AAAA"
e = torch.zeros(11, 4, dtype=torch.float64)
e[0, :] = -10
e[4:7, :] = 2
e[4:7, 0] = 10
e[7:11, :] = -100
e[9, 1] = 0
dur = DurationMixture(m=1, pi=((1.0,),) * 3, q=((0.5,),) * 3)
edges = EdgePrior()
a = e.tolist()
sc = Scores(n=4, u=a[0], cds=a[1:4], intron=a[4:7],
            start=a[7], stop=a[8], donor=a[9], acceptor=a[10])
for decoder in (ReferenceDecoder, DelayedEntryDecoder):
    print(decoder(TABLES[1], dur, edges).viterbi(x, sc))
print(viterbi(x, e, duration=dur, edges=edges))
```

Both independent scalar decoders return **2.128798989092109** with CDS
`[0,1)`, intron `[1,4)`, and both partial flags true. The closed-form
score is `6 - log(3) - 4*log(2)`: three intronic emissions, the phase-0
prefix prior, coding-entry and intron-exit priors, and two geometric
survival factors. The tensor decoder instead returns
**−2.4849066497880004**, CDS `[0,4)` with both partial flags true,
dropping the winning intron. This is a score error, not tie ordering.
